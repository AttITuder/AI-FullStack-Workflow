# Pi Agent FAQ

> Pi Agent 使用中的常见问题整理。按安装、模型、Provider、Agent Loop、Tool Calling、MCP、Extension、项目使用、企业落地、故障排查分类。

---

## 安装问题

## Q1: 安装失败怎么办？

### A

先按顺序排查：

1. **Node 版本**：确认满足环境要求。
2. **网络**：检查网络与镜像配置后重试。
3. **缓存**：清理包管理缓存后重装。

## Q2: 必须安装 Node 环境吗？

### A

部分环境可用独立可执行包，但建议准备 Node 环境以保证完整功能与依赖管理。

## Q3: 升级版本后出问题怎么办？

### A

- 查看更新说明，确认兼容性。
- 先小范围验证再全量切换。
- 必要时回退到上一稳定版本。

## 模型问题

## Q4: 如何选择 Pi Agent 的模型？

### A

- 复杂推理用强模型（如 Claude / GPT）。
- 快速任务用轻模型（如 DeepSeek / Qwen）。
- 敏感数据用本地模型。
- 按任务复杂度路由。

## Q5: 什么时候用本地模型？

### A

数据不出内网、合规要求高的场景。需评估算力与成本。

## Q6: 模型切换会影响工作流吗？

### A

通过 Provider 统一接口切换，对上层工作流透明，无感切换。

## Q7: 模型能力不足怎么办？

### A

- 换更强模型。
- 优化 Prompt 与上下文。
- 设计更好的工具，弥补模型短板。

## Provider 问题

## Q8: Provider 是什么？

### A

对模型服务提供方的统一抽象：屏蔽厂商 API 差异，提供统一接口、路由、成本控制与可观测。

## Q9: 如何接入多家模型？

### A

通过 Provider 配置多模型，按规则路由。避免厂商锁定。

## Q10: 如何避免厂商锁定？

### A

用统一 Provider 接口接入，模型切换对上层透明。

## Q11: Provider 配置变了需要改代码吗？

### A

不需要。配置与代码解耦，改配置即可。

## Agent Loop 问题

## Q12: Agent Loop 是什么？

### A

Agent 运行的基本循环：观察 → 规划 → 执行 → 反馈，循环直到目标完成或达到约束。

## Q13: Agent 会陷入死循环吗？

### A

可能。通过最大步数、超时与人工确认机制兜底。

## Q14: Agent 卡住不动怎么办？

### A

- 检查是否有明确目标。
- 提供更清晰的指令与上下文。
- 限制步数，让 Agent 收敛。

## Q15: 如何让 Agent 更自主？

### A

- 明确目标与边界。
- 提供充足工具。
- 逐步放开人工确认，先小范围验证。

## Tool Calling 问题

## Q16: Agent 能做什么工具操作？

### A

读文件、改代码、执行命令、查数据库、调 API 等，取决于接入的工具。

## Q17: 工具调用报错怎么办？

### A

- 检查命令可用性与路径。
- 检查权限与凭据。
- 查看错误日志，调整工具参数。

## Q18: 如何设计好工具？

### A

单一职责、输入明确、输出可解析、错误可读。

## Q19: 工具太多会乱吗？

### A

会。按需接入、职责单一、纳入版本库治理。

## MCP 问题

## Q20: MCP 是什么？

### A

模型上下文协议：用统一标准接入外部工具与数据源，让 Agent 能力可插拔扩展。

## Q21: MCP 服务接入失败怎么办？

### A

- 验证连通性与凭据。
- 确认协议兼容。
- 接入前单独验证，再挂到 Agent。

## Q22: 需要接入很多 MCP 服务吗？

### A

不需要。按需接入，避免工具泛滥，保持 Agent 聚焦。

## Q23: MCP 服务不可用会影响主流程吗？

### A

不应阻塞。做好失败降级，服务不可用时给出可读反馈。

## Extension 问题

## Q24: Extension 是什么？

### A

Pi Agent 的能力扩展机制，通过插件方式定制 Agent，支撑可组合、可扩展、可定制。

## Q25: 如何管理团队扩展？

### A

- 纳入版本库，随项目演进。
- 版本管理与依赖清晰。
- 先试点再推广。

## Q26: 扩展开发要注意什么？

### A

可组合、可复用、可维护，行为可审计。

## 项目使用问题

## Q27: Agent 不了解我的项目怎么办？

### A

- 让 Agent 先读关键文件。
- 提供项目结构与技术栈说明。
- 把规则与模块文档纳入上下文。

## Q28: 上下文太大效果变差怎么办？

### A

- 只加载任务相关文件。
- 优先文件引用与检索。
- 会话聚焦单一目标。

## Q29: 怎么让 Agent 遵守项目规范？

### A

- 规范写成 Rules 并纳入上下文。
- 委派时明确约束。
- 用验收清单检查。

## Q30: Agent 生成的代码不可靠怎么办？

### A

- 先让 Agent 给方案再执行。
- 用测试验证行为。
- 审查安全、性能与边界。

## 企业落地问题

## Q31: 企业内部如何建设 Agent？

### A

走"试点 → 沉淀 → 推广 → 治理 → 演进"路径，先验证价值再规模化。

## Q32: Agent 权限如何控制？

### A

最小权限，敏感操作人工确认，命令白名单。

## Q33: 数据安全如何保障？

### A

- 敏感数据走本地/合规模型。
- 权限最小化，行为可审计。
- 记录执行日志，保留痕迹。

## Q34: 如何评估 Agent 落地效果？

### A

用任务完成率、返工率、成本等指标评估，定期复盘。

## 成本优化问题

## Q35: Token 消耗太快怎么办？

### A

- 简单任务用轻模型。
- 控制上下文大小。
- 善用缓存与检索。
- 设定配额与告警。

## Q36: 批量任务如何省钱？

### A

- 批量任务走性价比模型。
- 模板化减少重复上下文。
- 错峰执行。

## 故障排查问题

## Q37: 连接超时或请求失败怎么办？

### A

- 检查网络与代理。
- 确认模型服务可用。
- 重试并查看错误日志。

## Q38: Agent 输出不符合预期怎么办？

### A

- 补充上下文与约束。
- 提供更贴近的示例。
- 拆解任务，缩小验证范围。

## Q39: 遇到文档没有的问题在哪找帮助？

### A

- 查看官方文档与社区。
- 沉淀踩坑经验回补到本文档。

## 总结

- 安装与升级问题先查 Node、网络与缓存。
- 模型与 Provider 核心是按任务路由、避免厂商锁定。
- Agent Loop 靠目标、步数限制与反馈闭环保证收敛。
- Tool 与 MCP 按需接入、单一职责、做好降级与治理。
- Extension 支撑可组合、可复用、可维护的定制扩展。
- 企业落地走试点到演进路径，守住权限、安全与成本。
- 故障排查从网络、日志、上下文三处入手。
