# Pi Agent Workflow

> 本章节核心。用 Agent 思维组织开发工作流：理解"观察-规划-执行-反馈"的 Agent 工作循环，并把它应用到软件开发、自动化任务、项目分析、Code Review、Flutter、Android 与企业场景。

---

## 为什么需要了解

Pi Agent 的价值不在单次生成，而在"用 Agent 循环组织复杂任务"。掌握 Agent 思维，才能设计出稳定、可复用、可扩展的工作流。本章突出 Agent 思维：Agent 不是被动应答，而是围绕目标持续规划、执行、反馈直至完成。

## 1. Agent 工作循环

### 核心循环

```text
观察
 ↓
规划
 ↓
执行
 ↓
反馈
```

### 每一步的含义

- **观察**：读取上下文，理解当前状态（项目结构、代码、报错）。
- **规划**：根据目标制定下一步行动，拆解为可执行步骤。
- **执行**：调用工具落实行动（读文件、改代码、跑命令）。
- **反馈**：查看执行结果，判断是否达成目标，决定继续或调整。

### Agent 思维要点

- **目标驱动**：Agent 围绕目标，而非单轮问答。
- **循环而非一次性**：失败是常态，关键是循环收敛。
- **工具是手脚**：没有工具调用，Agent 只是高级聊天。
- **反馈闭环**：每一步都观察结果，据实调整规划。

### 设计工作流的底层原则

1. 先观察再规划：不让 Agent 凭空决策。
2. 小步执行：每步可验证、可回滚。
3. 反馈即修正：观察结果驱动下一步。

## 2. 软件开发 Workflow

### 通用流程

```text
需求理解 → 架构对齐 → 任务拆解 → Agent 实现 → 验证 → Review
```

### 步骤详解

1. **需求理解**：明确目标、验收标准与约束。
2. **架构对齐**：让 Agent 感知项目结构、技术栈与规范。
3. **任务拆解**：把需求拆成可独立完成的任务。
4. **Agent 实现**：按拆解逐个实现，每步反馈。
5. **验证**：运行测试与构建，失败回环到实现。
6. **Review**：Agent 自检 + 人工审查后合入。

### Agent 思维要点

- 每个任务独立规划、执行、反馈。
- 用工具读真实代码，不做无依据的假设。
- 验收清单前置，让 Agent 自检后交付。

## 3. 自动化任务 Workflow

### 场景

- 批量生成、批量修改、定时任务、数据整理。

### 流程

```text
任务定义 → 模板化 → 批量执行 → 校验 → 报告
```

### 步骤详解

1. **任务定义**：明确输入、输出与处理规则。
2. **模板化**：把重复动作固化为可复用模板。
3. **批量执行**：Agent 循环处理每个输入。
4. **校验**：检查产出正确性，异常标记。
5. **报告**：汇总结果，输出可读报告。

### Agent 思维要点

- 用循环替代手工重复，成本与速度优势明显。
- 模板 + 校验，确保批量产出质量稳定。
- 失败任务单独标记，不阻塞整体。

## 4. 项目分析 Workflow

### 场景

- 理解遗留项目、梳理模块、评估技术债。

### 流程

```text
结构扫描 → 模块梳理 → 关联分析 → 风险输出 → 报告
```

### 步骤详解

1. **结构扫描**：读取目录、入口、依赖与配置。
2. **模块梳理**：逐模块理解职责与边界。
3. **关联分析**：梳理模块间依赖与调用关系。
4. **风险输出**：识别技术债、风险点与改进建议。
5. **报告**：输出结构化的分析报告。

### Agent 思维要点

- 观察优先：先扫描真实结构，再形成判断。
- 分而治之：大项目按模块逐个分析。
- 结论有据：每个判断关联真实代码位置。

## 5. Code Review Workflow

### 流程

```text
变更理解 → 维度审查 → 问题清单 → 人工复核 → 修复闭环
```

### 步骤详解

1. **变更理解**：读取 diff 与变更目的。
2. **维度审查**：按规范、安全、性能、逻辑审查。
3. **问题清单**：输出结构化问题与修改建议。
4. **人工复核**：判断意见合理性，定级处理。
5. **修复闭环**：修改后回归验证，确认无新问题。

### 审查维度

- **规范**：命名、格式、项目规范符合度。
- **安全**：敏感信息、输入校验、越权风险。
- **性能**：复杂度、资源消耗、热点路径。
- **逻辑**：边界条件、错误处理、并发安全。

### Agent 思维要点

- 用工具读取完整 diff 与相关上下文。
- 意见带依据：关联具体代码位置。
- 与人工审查配合，Agent 提问题、人做决策。

## 6. Flutter 项目实践

### 特点

- Flutter、Dart、GetX、Clean Architecture。
- 页面密集，UI 与状态管理耦合。

### Workflow

```text
1. 页面拆解 → Controller / Binding / View / Model
2. 架构对齐 → 让 Agent 感知分层规范
3. Agent 实现 → 按分层生成页面组件
4. 依赖处理 → pub 依赖说明与同步
5. 运行验证 → flutter analyze + flutter test
6. Review → 状态管理、命名、错误处理
```

### Agent 思维要点

- 每个页面一个任务循环：观察规范、规划分层、执行生成、反馈验证。
- 遵循项目分层规范（参考 `rules/flutter/` 与 `agents/flutter-agent/`）。
- 交付完整配套：Controller / Binding / View / Route。

## 7. Android 项目实践

### 特点

- Kotlin、Jetpack Compose、MVVM。
- 强调稳定性与可维护性。

### Workflow

```text
1. 需求 → 界面/逻辑拆解
2. 架构对齐 → ViewModel / Repository / Data
3. Agent 实现 → Compose UI + 业务逻辑
4. 依赖处理 → Gradle 同步
5. 运行验证 → 单元测试 + 构建
6. Review → 生命周期、协程、资源管理
```

### Agent 思维要点

- 关注生命周期与协程安全，Agent 规划阶段即纳入约束。
- 资源统一管理，避免硬编码。
- 构建验证是反馈环节的关键闸门。

## 8. 企业 Agent Workflow

### 特点

- 多人协作、规范严格、流程复杂。
- 强调可控、可审计、可追溯。

### Workflow

```text
1. 需求 → 工单/需求文档
2. 任务拆解 → 关联规范与验收标准
3. Agent 执行 → 遵循团队工具与规则
4. 多级验证 → 自动化测试 + Agent 自检 + 人工审查
5. 提交合并 → 规范提交 + PR 流程
6. 知识回流 → 沉淀工具、规则、工作流
```

### Agent 思维要点

- **治理优先**：权限控制、命令白名单、行为审计。
- **规范前置**：Agent 遵守团队 Rules，产出合规。
- **人工把关**：关键决策与最终合入由人决策。
- **持续演进**：成功实践回流为工具与规则，Agent 越用越强。
- **试点推广**：先小范围试点，验证后规模化。

## 总结

- Agent 工作循环"观察 → 规划 → 执行 → 反馈"是一切工作流的基础。
- 软件开发、自动化、项目分析、Review 各有流程，核心都是"先观察、小步执行、反馈闭环"。
- Flutter 与 Android 按技术栈细化，强调架构对齐与构建验证。
- 企业 Agent Workflow 强调治理、规范、人工把关与知识回流。
- 用 Agent 思维：目标驱动、循环收敛、工具落地、反馈修正。
