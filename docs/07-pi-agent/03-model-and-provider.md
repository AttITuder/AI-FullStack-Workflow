# Pi Agent 模型与 Provider

> 站在 Agent 架构的角度，讲解模型如何接入、Provider 如何抽象、多模型如何组合。核心是"Agent 任务驱动模型选型"，而非单一模型对比。

---

## 为什么需要了解

Pi Agent 是 Agent 框架，模型是它的"大脑"。理解模型架构与 Provider 抽象，才能按任务类型接入最合适的模型，并在成本、质量、合规之间取得平衡。

## 1. Pi Agent 模型架构

### 模型在 Agent 中的角色

- 模型是决策中枢：负责规划、判断与调用工具。
- 模型质量直接决定 Agent 产出质量。

### 架构分层

```text
Agent（规划/决策）
   ↓ 调用
模型接口（统一抽象）
   ↓ 路由
Provider（模型服务）
```

- Agent 面向任务，不关心底层模型细节。
- 通过统一接口切换模型，对上层透明。

### 关键点

- 模型可替换：同一工作流可切换不同模型。
- 按任务路由：复杂任务走强模型，简单任务走轻模型。
- 能力对齐：工具调用能力是 Agent 场景的必要条件。

## 2. Provider 概念

### 什么是 Provider

Provider 是对模型服务提供方的统一抽象：

- 屏蔽不同厂商的 API 差异。
- 提供统一的模型接口。
- 便于接入、切换与组合。

### Provider 的能力

| 能力 | 作用 |
| --- | --- |
| 统一接口 | 一套接口对接多家模型服务 |
| 路由 | 按任务/规则选择模型 |
| 成本控制 | 配额、限流与预算管理 |
| 可观测 | 用量、延迟与费用记录 |

### 为什么重要

- 企业可统一接入多家模型，不绑定单一厂商。
- 模型更新或切换对工作流无感。
- 数据合规可通过 Provider 策略控制。

## 3. 模型接入方式

### OpenAI

- 通用能力强，生态成熟。
- 适合作为通用主力与复杂任务候选。

### Anthropic

- 代码质量高，长上下文优秀。
- 适合复杂代码生成与长文档理解。

### DeepSeek

- 高性价比，推理能力强。
- 适合成本敏感与强推理任务。

### Qwen

- 中文优化，开源可控。
- 适合中文业务与合规要求高的场景。

### 本地模型

- 数据不出内网，合规可控。
- 适合敏感数据与企业内网部署。
- 算力要求高，需评估资源成本。

### 接入要点

- 通过统一 Provider 接口接入，避免厂商锁定。
- 密钥走环境变量与安全存储。
- 先小范围验证，再全量启用。

## 4. 多模型组合策略

### 按任务复杂度路由

| 任务类型 | 推荐模型 |
| --- | --- |
| 复杂推理 | Claude / GPT |
| 快速任务 | DeepSeek / Qwen |
| 代码生成 | Claude / GPT |
| 中文业务 | Qwen / DeepSeek |
| 敏感数据 | 本地模型 |

### 组合原则

- **质量优先**：复杂分析、架构权衡走强模型。
- **成本优先**：批量、简单任务走轻模型。
- **合规优先**：敏感数据走本地或合规来源。
- **稳定性优先**：核心流程用经过验证的模型。

### 组合示例

```text
Agent 收到任务
   ↓
判断复杂度
   ├── 复杂 → Claude / GPT（推理）
   ├── 简单 → DeepSeek / Qwen（快速）
   └── 敏感 → 本地模型（合规）
```

### 落地方式

- 通过 Provider 配置多模型，按规则路由。
- 路由对工作流透明，切换无感。
- 用真实任务评测集评估切换影响。

## 5. 企业模型选择方案

### 评估维度

1. **任务盘面**：梳理 Agent 承载的任务类型。
2. **成本预算**：按 Token 消耗规划模型组合。
3. **合规要求**：数据敏感度决定模型来源。
4. **稳定性**：核心流程依赖经过验证的模型。

### 推荐配置模板

| 角色 | 推荐 | 说明 |
| --- | --- | --- |
| 默认任务 | 均衡国产模型 | 中文 + 成本 |
| 复杂推理 | 强推理模型 | 深度兜底 |
| 快速批量 | 性价比模型 | 成本控制 |
| 敏感数据 | 本地/合规模型 | 数据可控 |
| 代码核心 | 高质量模型 | 产出质量 |

### 长期维护

- 模型配置纳入版本库（不含密钥）。
- 模型更新先小范围灰度，再全量。
- 定期复盘成本与质量，动态调整路由。
- 与 `docs/02-models/10-model-selection.md` 联动。

## 最佳实践

1. 用 Provider 抽象模型池，避免厂商锁定。
2. 按任务复杂度路由：复杂走强模型、简单走轻模型。
3. 中文、成本、合规场景差异化选型。
4. 本地模型兜底敏感数据，守住合规底线。
5. 模型切换先小范围灰度验证。

## 常见问题

**Q1：Agent 必须用最强模型吗？**

不是。按任务复杂度路由，简单任务用轻模型可显著降本。

**Q2：如何避免厂商锁定？**

通过 Provider 统一接口接入，切换对上层透明。

**Q3：本地模型值得用吗？**

敏感数据与合规场景值得；需评估算力与成本。

## 本章总结

- 模型是 Agent 的决策中枢，通过统一接口抽象，可替换、可按任务路由。
- Provider 屏蔽厂商差异，提供统一接口、路由、成本控制与可观测。
- 接入方式覆盖 OpenAI、Anthropic、DeepSeek、Qwen 与本地模型。
- 多模型组合核心原则：质量、成本、合规、稳定四维权衡。
- 企业方案强调任务盘面、预算、合规与灰度验证。
