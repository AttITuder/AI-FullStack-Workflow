# Pi Agent 安装与环境准备

> 面向开发者的环境准备指南。以稳定可复现为原则，不绑定具体版本号，不涉及具体配置项。

---

## 为什么需要了解

Pi Agent 是 Agent 框架类工具，安装与接入比普通插件多一步"环境初始化"。本章覆盖环境要求、安装方式、初始化、第一次运行、基础项目接入与常见问题。

## 1. 环境要求

### 操作系统

- 支持主流桌面系统（macOS、Linux、Windows）。
- 服务器与 CI 环境也可部署，便于自动化运行。

### Node 环境

- 需要可用的 Node.js 运行环境。
- 包管理工具（npm / pnpm / yarn 任一）可用于安装依赖。

### 开发环境

- 需要一个可用的终端。
- 安装 Git，用于项目接入与版本管理。
- 依据项目技术栈准备对应工具链（Java、Dart、Node 等）。

### 账号与密钥

- 使用模型服务需要对应的 API Key。
- 密钥通过环境变量或配置管理，不要硬编码进仓库。

### 验证环境

```bash
node --version
npm --version
git --version
```

确认基础工具可用后，即可继续。

## 2. 安装方式

### 全局安装

- 通过包管理工具全局安装，即可在任何项目中使用。

### 项目内安装

- 在项目目录内安装，依赖与版本随项目管理。
- 适合团队共享同一版本，便于复现。

### 二进制 / 独立包

- 部分环境可下载独立可执行包，免 Node 依赖。
- 适合 CI 或精简环境部署。

### 安装选择建议

| 场景 | 推荐方式 |
| --- | --- |
| 个人开发 | 全局安装 |
| 团队项目 | 项目内安装 |
| CI 自动化 | 独立包 / 项目内安装 |

## 3. 初始化环境

### 初始化流程

1. 完成安装。
2. 配置模型服务访问凭据。
3. 验证基础连通性。

### 凭据配置

- 通过环境变量注入 API Key。
- 密钥不入版本库，通过 `.gitignore` 排除。

### 配置验证

```bash
# 示例，验证凭据与连通性
pi-agent --version
```

确认版本与凭据可用后进入下一步。

## 4. 第一次运行

### 启动

- 在项目目录启动 Pi Agent。
- 确认它能感知当前项目上下文。

### 基本交互

- 提出一个简单任务（例如"解释项目结构"）。
- 观察 Agent 的规划与执行过程，理解 Agent Loop。
- 验证它能读取文件、执行命令。

### 首次自检清单

- [ ] 能启动并感知项目
- [ ] 能完成一次简单任务
- [ ] 工具调用链路正常
- [ ] 失败时能给出可读反馈

## 5. 基础项目接入

### 已有项目

- 打开项目目录，让 Agent 感知结构。
- 提供关键文件说明，帮助 Agent 理解约定。

### 新项目

- 先初始化项目骨架（Git、README、目录结构）。
- 再让 Agent 参与初始代码搭建。

### 团队接入

- 把常用工具、规则与工作流沉淀到项目。
- 通过配置随版本库管理，新成员一键接入。
- 保持接入步骤写入项目 README。

## 6. 常见问题

### 安装失败

**现象**：安装报错或无法启动。

**处理**：检查 Node 版本与网络，清理缓存后重装。

### 密钥未配置

**现象**：请求失败或提示鉴权。

**处理**：确认环境变量已正确注入，检查密钥状态。

### 无法感知项目

**现象**：Agent 不了解当前项目。

**处理**：确认在项目目录运行，提供关键文件上下文。

### 工具调用失败

**现象**：Agent 调用工具报错。

**处理**：检查命令可用性、路径与权限。

## 最佳实践

1. 团队统一 Node 版本与安装方式，写入项目 README。
2. 密钥走环境变量，通过 `.gitignore` 排除，杜绝入库。
3. 新项目先沉淀工具与规则，再让 Agent 参与开发。
4. 升级前查看更新说明，小范围验证后再全量。

## 常见问题

**Q1：不装 Node 能运行吗？**

部分环境可用独立可执行包，但建议准备 Node 环境以保证完整功能。

**Q2：Windows 上体验如何？**

主流桌面系统均可支持，注意终端与工具链兼容性。

**Q3：安装失败先查什么？**

先查 Node 版本、网络与包管理缓存。

## 本章总结

- 环境要求：主流系统、Node 环境、Git 与项目工具链。
- 安装方式：全局 / 项目内 / 独立包，按场景选择。
- 初始化：配置模型凭据，验证连通性。
- 第一次运行：验证感知项目、完成任务、工具调用链路。
- 基础接入：已有项目直接使用，新项目先搭骨架，团队统一配置。
- 常见问题集中在安装、凭据、项目感知与工具调用四类。
