# CodeBuddy 开发 Workflow

> 本章节核心。围绕企业研发场景，讲解如何用 CodeBuddy 组织完整的开发流程。突出企业场景的规范、验收与协作。

---

## 为什么需要了解

CodeBuddy 的价值核心是"企业研发场景的任务委派"。掌握不同场景下的工作流，才能让团队稳定获得高质量产出，并在规范与效率之间取得平衡。本文突出企业研发场景，覆盖日常、新功能、Bug、重构、Review 及多技术栈实践。

## 1. 日常开发 Workflow

### 主循环

```text
需求分析 → 任务拆分 → AI 实现 → 测试 → Review
```

### 步骤详解

1. **需求分析**：理解业务需求，明确验收标准。
2. **任务拆分**：把需求拆成可执行的开发任务。
3. **AI 实现**：委派 CodeBuddy 生成/修改代码。
4. **测试**：运行构建与测试，迭代修复。
5. **Review**：AI 自检 + 人工审查，确认后合并。

### 企业场景要点

- **规范先行**：委派前明确团队 Rules 与代码规范。
- **小步交付**：一次任务聚焦一个改动，便于审查回滚。
- **验证闭环**：AI 产出必须通过测试验证。

## 2. 新功能开发

### 流程

```text
需求
 ↓
设计
 ↓
任务拆分
 ↓
AI生成
 ↓
人工Review
```

### 步骤详解

1. **需求**：功能目标、用户故事、验收标准。
2. **设计**：技术方案、数据模型、接口契约。
3. **任务拆分**：拆成可独立委派的子任务。
4. **AI 生成**：CodeBuddy 逐任务生成代码。
5. **人工 Review**：确认质量后合并。

### 委派提示要点

- 提供设计文档与技术约束。
- 指定遵循的项目规范。
- 要求分步实现、逐步确认。

## 3. Bug 修复 Workflow

### 流程

```text
1. 提供现象 → 报错信息、复现步骤、相关日志
2. 定位根因 → AI 读代码找原因
3. 确认方案 → 说明修复思路后再动手
4. 最小修改 → 只改必要代码
5. 验证修复 → 复现场景 + 相关测试
6. 补充说明 → 记录根因与修复逻辑
```

### 企业场景要点

- **根因优先**：禁止"猜着改"，先定位根因。
- **最小改动**：避免修复引入新问题。
- **验证闭环**：必须证明问题已解决。

## 4. 重构 Workflow

### 流程

```text
1. 明确目标 → 重构范围与预期收益
2. 建立基线 → 确保现有测试通过
3. 拆分重构 → 小步提交，每步可验证
4. 依赖更新 → 同步引用与文档
5. 回归测试 → 确认行为未变
6. 审查合并 → 关注可读性一致性
```

### 企业场景要点

- **行为不变**：重构只改内部结构，不改外部行为。
- **测试保护**：重构前必须有测试兜底。
- **分批委派**：大型重构拆成多个小任务。

## 5. Code Review Workflow

### 流程

```text
1. 提供上下文 → 变更范围、目的、关联需求
2. AI 审查 → 规范、安全、性能、逻辑
3. 输出意见 → 结构化问题清单 + 建议
4. 人工复核 → 判断意见合理性
5. 修复迭代 → 按意见修改并验证
6. 最终确认 → 通过标准
```

### 审查维度

- **规范**：命名、格式、项目规范符合度。
- **安全**：敏感信息、输入校验、越权风险。
- **性能**：复杂度、资源消耗、热点路径。
- **逻辑**：边界条件、错误处理、并发安全。

## 6. Android 项目实践

### 特点

- 技术栈：Kotlin、Jetpack Compose、MVVM。
- 企业 Android 项目强调稳定性、可维护性。

### Workflow

```text
1. 需求 → 界面/逻辑拆解
2. 架构对齐 → ViewModel / Repository / Data
3. AI 生成 → Compose UI + 业务逻辑
4. 依赖处理 → Gradle 同步
5. 运行验证 → 单元测试 + 构建
6. Review → 生命周期、协程、资源管理
```

### 委派要点

- 关注生命周期与协程安全。
- 资源（字符串、样式）统一管理。

## 7. Flutter 项目实践

### 特点

- 技术栈：Flutter、Dart、GetX、Clean Architecture。
- 页面密集，UI 与状态管理耦合。

### Workflow

```text
1. 需求 → 页面/功能拆解
2. 架构对齐 → Controller / Binding / View / Model
3. AI 生成 → 按分层生成页面组件
4. 依赖处理 → pub 依赖说明与同步
5. 运行验证 → flutter analyze + flutter test
6. Review → 状态管理、命名、错误处理
```

### 委派要点

- 遵循项目分层规范（参考 `rules/flutter/` 与 `agents/flutter-agent/`）。
- 每个页面交付完整配套（Controller / Binding / View / Route）。

## 8. 企业团队 Workflow

### 特点

- 多人协作、规范严格、流程复杂。
- 强调可控、可审计、可追溯。

### Workflow

```text
1. 需求 → 工单/需求文档
2. 任务拆分 → 关联规范与验收标准
3. AI 实现 → 遵循团队 Rules 与模板
4. 多级验证 → 自动化测试 + AI 审查 + 人工审查
5. 提交合并 → 规范提交信息 + PR 流程
6. 知识回流 → 沉淀 Prompt / Rules / 经验
```

### 企业场景要点

- **规范前置**：AI 产出必须符合团队 Rules。
- **人工验收**：关键决策由人把控。
- **可追溯**：需求、任务、代码、提交全程关联。
- **知识沉淀**：每次成功实践回流到知识库。
- **团队推广**：试点项目验证效果后再全团队推广。

## 总结

- CodeBuddy 的价值核心是"企业研发场景的任务委派"，AI 承担核心编码执行。
- 日常开发遵循"需求分析 → 任务拆分 → AI 实现 → 测试 → Review"主循环。
- 新功能、Bug、重构、Review 各有工作流，核心是"规范先行、小步、验证闭环"。
- Android 与 Flutter 按技术栈调整流程细节。
- 企业团队强调规范前置、人工验收、可追溯与知识回流。
