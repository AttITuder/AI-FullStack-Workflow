# CodeBuddy 最佳实践

> 面向企业长期维护项目的实战经验总结。围绕 Prompt 设计、Context 管理、项目规则、AI 代码规范、Git 协作、团队推广、大型项目与常见错误，沉淀可直接落地的做法。

---

## 为什么需要了解

CodeBuddy 面向企业研发场景，产出质量与"规范落地"强相关。本文把企业实战中验证过的经验固化为最佳实践，帮助团队稳定获得高质量产出，并顺畅推广。

## 1. Prompt 设计

### 结构化委派

- **说清背景**：项目类型、技术栈、现有架构。
- **说清任务**：要做什么，范围与边界。
- **说清约束**：规范、风格、禁止事项。
- **说清输出**：期望文件、结构、验收标准。

### 中文优先

- 中文需求用清晰的中文描述，减少理解偏差。
- 结合团队术语，保持表达一致。

### 提供示例

- 给出"对的样子"（已有代码、期望风格）。
- 示例越接近目标场景，产出越准确。

### 用清单约束

- 委派末尾附验收清单，让 AI 自检后交付。

## 2. Context 管理

### 提供足够但不过量的上下文

- 只给任务相关的文件与信息。
- 大型项目优先用文件引用与检索。

### 明确项目上下文

- 让 AI 先读关键文件（入口、配置、数据模型）再动手。
- 把团队 Rules 纳入上下文，约束产出风格。

### 会话聚焦

- 一次会话聚焦一个任务，避免上下文污染。
- 完成一个任务后开启新会话。

## 3. 项目规则

### 规则前置

- 编码规范、命名约定、架构约束在委派时明确。
- 参考 `rules/` 目录，把团队规范纳入上下文。

### 可执行可检查

- 规则要可执行、可检查，避免模糊表述。
- 用验收清单检查 AI 是否遵守。

### 持续维护

- 根据产出反馈修订规则。
- 规则与 Prompt、Agent 配置保持同步。

## 4. AI 代码规范

### 统一风格

- 让 AI 遵循项目既有风格，参考现有代码。
- 用 Rules 约束命名、格式与结构。

### 质量红线

- 安全：敏感信息、输入校验、越权风险。
- 性能：复杂度、资源消耗、热点路径。
- 健壮性：边界条件、错误处理、并发安全。

### 测试配套

- 要求 AI 为改动生成测试。
- 用测试验证行为，不盲信输出。

## 5. Git 协作

### 规范提交

- 要求 AI 提交遵循 Conventional Commit 规范。
- 每次改动聚焦一件事。

### 小步提交

- 避免一次提交大量无关改动。
- 每个提交可独立验证、可回滚。

### 审查前置

- AI 改动合并前经过 AI 自检 + 人工审查。
- 使用 PR 流程，保留审查记录。

## 6. 团队推广方式

### 试点先行

- 先在一个项目试点，验证效果与坑点。
- 收集反馈后形成推广方案。

### 统一配置

- Rules、Prompt、Agent 配置纳入版本库。
- 新成员按 README 一键配置，体验一致。

### 培训与文档

- 编写团队使用指南与最佳实践文档。
- 分享成功案例，带动团队采用。

### 指标评估

- 用任务完成率、返工率、成本等指标评估效果。
- 定期复盘，持续优化。

## 7. 大型项目使用

### 分而治之

- 把大型任务拆成可独立完成的子任务。
- 一次处理一个模块，保持上下文可控。

### 善用检索

- 用检索/文件引用定位相关代码，避免全量读库。
- 让 AI 基于真实代码做决策。

### 维护模块文档

- 为关键模块维护简短说明（用途、结构、约定）。
- AI 可快速理解模块，产出更贴合现状。

### 渐进集成

- 分阶段生成与验证，避免一次大改无法回滚。

## 8. 常见错误

### 错误一：不提供上下文

让 AI 凭空猜项目结构，产出牛头不对马嘴。

**修正**：先让 AI 读代码库，再给任务。

### 错误二：一次委派太多

让 AI 一次性完成巨大任务，质量失控。

**修正**：拆成小任务，逐步确认。

### 错误三：盲目信任输出

不经验证就合入 AI 代码。

**修正**：测试 + 审查双保险。

### 错误四：不沉淀规则

每次靠人肉纠正，团队没有积累。

**修正**：把教训写进 Rules 与 Prompt。

### 错误五：上下文塞满

把整个仓库塞给 AI，成本高效果差。

**修正**：检索 + 文件引用，按需加载。

### 错误六：忽略账号安全

团队共享账号或密钥硬编码。

**修正**：独立账号 + 密钥管理。

### 错误七：跳过审查环节

让 AI 直接合并代码，绕过质量防线。

**修正**：审查前置，人工把关关键变更。

## 总结

- Prompt 讲究"背景、任务、约束、输出"四要素 + 示例 + 清单，中文场景用中文表达。
- Context 提供"足够但不过量"，会话聚焦单一任务。
- 项目规则与 AI 代码规范前置，让产出符合团队标准。
- Git 协作强调规范提交、小步提交、审查前置。
- 团队推广试点先行、统一配置、培训赋能、指标评估。
- 大型项目分而治之、善用检索、渐进集成。
- 避开常见错误，用工程手段保证产出质量。
