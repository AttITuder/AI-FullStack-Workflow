# CodeBuddy FAQ

> CodeBuddy 使用中的常见问题整理。按安装、模型、账号、上下文、代码质量、Agent、企业使用、成本优化、故障排查分类。

---

## 安装问题

## Q1: CodeBuddy 插件安装失败怎么办？

### A

先按顺序排查：

1. **兼容性**：确认 IDE 版本与插件兼容。
2. **网络**：检查网络与镜像配置后重试。
3. **缓存**：清理 IDE 缓存后重装。

## Q2: 客户端无法启动怎么办？

### A

- 检查系统环境与依赖。
- 重新下载安装包安装。
- 查看日志定位启动失败原因。

## Q3: IDE 中插件不生效怎么办？

### A

- 确认插件已启用。
- 重启 IDE 让插件加载。
- 检查 IDE 版本是否被支持。

## 模型问题

## Q4: 如何选择 CodeBuddy 的模型？

### A

- 补全/简单生成用快速模型。
- 日常开发用均衡模型。
- 疑难调试与审查用推理模型。
- 按任务复杂度路由。

## Q5: 不同模型产出风格不一致怎么办？

### A

通过团队 Rules 统一约束产出风格，让任何模型都按同一标准输出。

## Q6: 可以接入第三方模型吗？

### A

可通过网关将国产模型、GPT、Claude、DeepSeek、Qwen 等纳入统一工作流，按任务路由。

## 账号问题

## Q7: 需要什么账号才能用 CodeBuddy？

### A

通常需要注册账号，企业可通过团队账号统一管理。

## Q8: 登录失败或鉴权报错怎么办？

### A

- 重新登录账号。
- 检查账号状态与网络。
- 确认账号具备对应权限。

## Q9: 团队共享账号安全吗？

### A

不建议共享。建议为成员分配独立账号或使用企业统一账号体系，便于管理与审计。

## 上下文问题

## Q10: CodeBuddy 不了解我的项目怎么办？

### A

- 让 AI 先读关键文件（入口、配置、数据模型）。
- 提供项目结构说明与技术栈信息。
- 把 Rules 与模块文档纳入上下文。

## Q11: 上下文太大效果变差怎么办？

### A

- 只加载任务相关文件，避免噪声。
- 优先使用文件引用与检索。
- 会话聚焦单一任务。

## Q12: 如何让 AI 记住项目约定？

### A

- 把约定写成 Rules 与模块文档。
- 每次委派时引用或自动加载。
- 通过配置固化常用约定。

## 代码质量问题

## Q13: 生成的代码不靠谱怎么办？

### A

- 先让 AI 给方案，人确认后再生成。
- 用测试验证行为，不盲信输出。
- 审查安全、性能与边界条件。

## Q14: 如何提高生成代码准确性？

### A

- 提供现有代码示例作为风格参照。
- 明确技术栈、架构与约束。
- 用验收清单约束输出。

## Q15: 代码引入了安全隐患怎么办？

### A

- 审查环节增加安全维度检查。
- 通过 Rules 约束安全编码规范。
- 关键安全操作人工把控。

## Agent 问题

## Q16: AI Agent 会乱改代码吗？

### A

存在风险。通过权限控制、小步委派、人工审查控制。让 AI 先给方案再执行。

## Q17: AI 任务失败怎么办？

### A

- 查看失败日志，定位卡住的环节。
- 提供更明确的指令与上下文。
- 拆分子任务，分步验证。

## Q18: 如何让 AI 更高效？

### A

- 给 AI 明确的目标与边界。
- 配置专用 Agent 固化能力。
- 建立验收清单，减少返工。

## Q19: 多个 Agent 如何协作？

### A

- 明确分工与交接物。
- 通过工作流编排（参考 `docs/16-case-study/`）。
- 每个 Agent 产出独立可验证。

## 企业使用问题

## Q20: 企业如何统一配置？

### A

- Rules、Prompt、Agent 配置纳入版本库。
- 新成员按 README 一键配置。
- 企业账号统一管理。

## Q21: 数据安全如何保障？

### A

- 敏感数据走合规模型来源。
- 配置权限策略与命令白名单。
- 记录 AI 执行行为，保留审计痕迹。

## Q22: 如何保证产出风格统一？

### A

- 团队 Rules 前置到委派环节。
- 统一 Prompt 模板与 Agent 配置。
- 自动化检查 + 人工审查防线。

## Q23: 如何向团队推广 CodeBuddy？

### A

- 试点先行，验证效果。
- 统一配置与培训文档。
- 用指标评估效果，持续优化。

## 成本优化问题

## Q24: Token 消耗太快怎么办？

### A

- 简单任务用性价比模型。
- 控制上下文大小。
- 利用缓存减少重复消耗。
- 通过网关设定配额与告警。

## Q25: 如何评估模型性价比？

### A

- 建立任务完成率、返工率、成本指标。
- 定期复盘各模型表现。
- 用真实任务评测集验证切换影响。

## Q26: 批量任务如何省钱？

### A

- 简单批量任务用快速/廉价模型。
- 提前规划上下文，避免重复加载。
- 错峰执行，利用优惠时段。

## 故障排查问题

## Q27: 连接超时或请求失败怎么办？

### A

- 检查网络与代理。
- 确认服务可用状态。
- 重试并查看错误日志。

## Q28: 输出截断怎么办？

### A

- 任务过大时拆分子任务。
- 精简上下文与输出要求。
- 分步请求避免单次过长。

## Q29: 中文需求理解不准怎么办？

### A

- 用更结构化的中文描述，明确背景与约束。
- 提供示例与验收标准。
- 结合团队术语，减少歧义。

## Q30: 结果不符合预期怎么办？

### A

- 补充上下文与约束，重新委派。
- 提供更贴近的示例。
- 拆解任务，缩小验证范围。

## Q31: 遇到文档没有的问题在哪找帮助？

### A

- 查看官方文档与社区。
- 沉淀踩坑经验回补到本文档。

## 总结

- 安装与账号问题优先查兼容性、网络、登录。
- 模型与上下文核心是"按任务路由、按需加载"。
- 代码质量靠测试、审查与 Rules 保障。
- Agent 强调规划先行、权限控制、人工验收。
- 企业使用统一配置、守住安全、控制成本、试点推广。
- 故障排查从网络、日志、上下文三处入手。
