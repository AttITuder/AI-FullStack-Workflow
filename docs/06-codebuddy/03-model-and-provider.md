# CodeBuddy 模型与 Provider

> 站在 AI FullStack Workflow 的角度，讲解 CodeBuddy 的模型体系、能力分工与企业模型组合方案。不写简单模型介绍。

---

## 为什么需要了解

CodeBuddy 面向国内企业研发场景，模型选型的核心不是"追最强"，而是"在企业成本、中文场景、合规要求下达到最优产出"。理解模型能力维度的差异，并掌握多模型组合方案，是让 CodeBuddy 稳定产出的关键。

## 1. CodeBuddy 模型体系

CodeBuddy 围绕企业研发任务组织模型：

| 类型 | 定位 | 典型任务 |
| --- | --- | --- |
| 快速模型 | 轻快低成本 | 补全、简单生成、批量 |
| 均衡模型 | 通用主力 | 日常开发、文档 |
| 推理模型 | 深度推理 | 疑难调试、架构分析 |
| 旗舰模型 | 高质量产出 | 核心功能、复杂任务 |

模型体系的逻辑：**任务复杂度决定模型深度**。企业实践中按角色组合，而非单一模型。

## 2. 模型能力说明

### Coding 能力

- 决定代码生成的质量、语法正确性与风格一致性。
- 中文需求下的代码生成是本土模型的核心优势。

### Reasoning 能力

- 决定多步逻辑推导能力：疑难 Bug、架构权衡、算法。
- 推理模型在企业疑难场景兜底。

### Context 能力

- 决定模型能同时理解多少代码与文档。
- 大型企业项目需要足够的上下文支撑。

### Vision 能力

- 决定模型能否理解 UI 设计稿、截图与图表。
- 支撑"设计稿转代码"与界面排查。

### Tool Calling 能力

- 决定模型能否调用外部工具：命令、文件、服务。
- 是 Agent 化工作流的基石。

## 3. 模型选择策略

### 按任务路由

| 任务 | 模型选择 |
| --- | --- |
| 代码补全 | 快速模型 |
| 日常生成 | 均衡模型 |
| 疑难调试 | 推理模型 |
| 核心功能 | 旗舰模型 |
| 视觉任务 | 多模态模型 |

### 结合主流模型

- **国产模型**：中文能力优秀，成本低，符合国内合规要求。
- **GPT**：通用能力强，生态完整。
- **Claude**：代码质量高，长上下文优秀。
- **DeepSeek**：高性价比，推理能力强。
- **Qwen**：中文优化，开源可控。

### 选择原则

- **中文优先**：国内业务场景优先中文优化模型。
- **成本优先**：批量任务优先性价比模型。
- **质量优先**：核心功能优先旗舰模型。
- **合规优先**：敏感数据走合规模型来源。

## 4. 企业模型组合方案

### 组合示例

| 场景 | 推荐 | 说明 |
| --- | --- | --- |
| 快速生成 | 国产模型 | 低成本、响应快 |
| 复杂分析 | 高级推理模型 | 深度思考兜底 |
| 代码 Review | 强推理模型 | 审查质量高 |
| 日常开发 | 均衡模型 | 通用稳定 |
| 中文业务 | 中文优化模型 | 本土优势 |
| 敏感数据 | 合规/本地 | 数据可控 |

### 路由原则

- **按复杂度**：简单走快速，复杂走推理/旗舰。
- **按成本**：批量任务走性价比模型。
- **按场景**：中文、视觉、审查差异化选型。
- **按合规**：数据敏感度决定模型来源。

### 落地方式

- 通过模型网关统一管理多个 Provider。
- CodeBuddy 场景与团队其他工具共享模型池。
- 路由规则对上层工作流透明，切换无感。

## 企业如何选择

### 配置前评估

1. **盘点任务**：区分补全、生成、推理、审查、视觉。
2. **明确合规**：数据敏感度决定模型来源。
3. **设定预算**：按 Token 消耗规划组合。

### 推荐配置模板

| 角色 | 推荐 | 说明 |
| --- | --- | --- |
| 默认开发 | 均衡/国产模型 | 中文 + 成本 |
| 疑难推理 | 推理模型 | 深度兜底 |
| 代码审查 | 强推理模型 | 审查质量 |
| 批量生成 | 快速/性价比模型 | 成本控制 |
| 敏感数据 | 合规/本地 | 数据可控 |

### 长期维护

- 模型配置纳入版本库（不含密钥）。
- 模型更新先小范围验证，再全量切换。
- 与 `docs/02-models/10-model-selection.md` 保持联动。
- 定期复盘性价比，动态调整。

## 最佳实践

1. 按任务复杂度选择模型深度，避免一刀切。
2. 国产模型打底、旗舰/推理兜底，组合使用。
3. 用网关抽象模型池，切换对工作流透明。
4. 中文、成本、合规等场景差异化选型。

## 常见问题

**Q1：CodeBuddy 支持哪些模型？**

围绕企业场景组织模型体系，并可通过网关接入国产、GPT、Claude、DeepSeek、Qwen 等。

**Q2：什么时候用推理模型？**

疑难调试、复杂分析、代码审查等深度任务。

**Q3：如何降低成本？**

简单任务用性价比模型，控制上下文，利用缓存。

## 本章总结

- CodeBuddy 模型体系围绕企业任务组织：快速、均衡、推理、旗舰。
- 能力维度覆盖 Coding、Reasoning、Context、Vision、Tool Calling。
- 企业组合方案按场景路由：快速生成用国产、复杂分析用推理、Review 用强推理。
- 合规、中文、成本是本土企业选型的核心考量。
