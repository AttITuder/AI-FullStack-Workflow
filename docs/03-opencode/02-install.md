# OpenCode 安装

> 面向实际开发者的安装指南。以稳定可复现为原则，不绑定具体过期版本号。

---

## 为什么需要了解

安装是一切工作的前提。本文覆盖环境要求、安装方式、初始配置、第一次运行、项目接入方式与常见问题，帮助开发者在自己的机器上快速跑通 OpenCode，并让团队按统一方式落地。

## 1. 环境要求

### 操作系统

- 推荐：macOS、Linux（WSL/Linux 桌面）。
- 支持：Windows（建议使用 WSL 以获得完整终端体验）。
- OpenCode 以终端为运行环境，macOS 与 Linux 生态最为顺滑。

### Node 环境

- OpenCode 基于 Node.js 生态运行，需要可用的 Node 运行时。
- 建议通过官方版本管理工具（如 nvm、fnm）安装长期维护（LTS）版本。
- 需要 `npm`（或 `pnpm` / `yarn`）包管理器用于全局安装。

### Git

- 需要已安装并配置好的 Git。
- 配置用户信息（`user.name` / `user.email`），OpenCode 的部分能力依赖 Git 工作区。

### 编辑器

- 建议：VS Code、Neovim 或任意支持终端的编辑器。
- OpenCode 本身运行在终端，编辑器用于人工查看与修改结果。

### 验证环境

```bash
node --version
npm --version
git --version
```

确认以上命令都能输出版本号后，即可继续安装。

## 2. 安装方式

### 官方方式

- 官方提供全局安装命令，通过包管理器一条命令完成安装。
- 安装命令以官方文档为准，使用前可先确认版本与平台要求。

```bash
npm install -g <opencode-package>
```

### 包管理器方式

- 若使用 `pnpm` 或 `yarn`，也可通过对应包管理器全局安装。

```bash
pnpm add -g <opencode-package>
# 或
yarn global add <opencode-package>
```

- 部分平台提供独立安装脚本，适合不想引入 Node 工具链的环境。

### 验证安装

安装完成后，在终端输入 OpenCode 的命令名，出现版本号或帮助信息即安装成功。

```bash
<opencode-command> --version
```

## 3. 初始配置

### 配置文件

- OpenCode 在用户目录下维护配置文件（路径随平台不同）。
- 配置文件用于声明 Provider、模型、权限等基础设置。

### 基础配置项

- **Provider**：声明要使用的模型提供方（详见 `03-provider.md`）。
- **API Key**：通过环境变量或密钥管理方式注入，避免硬编码到文件。
- **权限策略**：设置 AI 可执行的命令范围，遵循最小权限原则。
- **默认模型**：指定日常使用的默认模型。

### 配置管理建议

- 配置文件中**不要写入真实密钥**，统一通过环境变量引用。
- 团队可将非敏感配置纳入版本库，敏感配置用 `.env` 本地管理。

## 4. 第一次运行

### 启动

在项目目录中启动 OpenCode，它会检测当前项目并加载上下文。

### 基本交互

- 用自然语言提出一个简单任务（例如"解释这个项目的结构"），验证链路是否打通。
- 观察 AI 是否能读取项目文件、理解上下文。
- 若使用 API Provider，确认能正常完成模型调用。

### 首次自检清单

- [ ] 版本命令正常输出
- [ ] Provider 配置生效
- [ ] 能读取当前项目文件
- [ ] 一次简单对话能正常返回

## 5. 项目接入方式

### 已有项目

- 在项目根目录启动 OpenCode，它会自动加载项目上下文。
- 建议在项目内补充 `rules` 与提示词，约束 AI 产出风格。

### 新项目

- 先初始化项目骨架（Git、目录结构、README），再启动 OpenCode。
- 让 AI 在清晰的项目结构中工作，产出质量更稳定。

### 团队接入

- 将团队规范（Rules、Provider 配置、常用 Prompt）纳入版本库。
- 新成员克隆项目后，按 README 指引完成配置即可使用。
- 使用 `.env` 管理个人密钥，避免共享敏感信息。

## 6. 常见安装问题

### 权限问题

**现象**：全局安装失败，提示 `EACCES`（无权限写入目录）。

**处理**：

- 优先配置 npm 全局目录为当前用户可写路径，避免使用 `sudo` 安装。
- 检查 `npm config get prefix`，按官方建议调整目录权限。

### 网络问题

**现象**：安装或更新超时、下载失败。

**处理**：

- 检查网络连接与代理设置。
- 必要时配置 npm 镜像源（如国内镜像）以加速下载。
- 重试安装，部分失败源于瞬时网络波动。

### 环境变量问题

**现象**：命令找不到、API Key 不生效。

**处理**：

- 确认 OpenCode 命令在 `PATH` 中（必要时重开终端或重新加载 `shell` 配置）。
- 确认 API Key 变量名正确、已导出到当前会话。
- 检查 `.env` 文件是否被正确加载。

### 版本兼容问题

**现象**：升级后行为异常或依赖报错。

**处理**：

- 确认 Node 版本符合要求。
- 升级/降级到稳定版本组合。
- 清理旧缓存后重新安装。

## 最佳实践

1. 使用版本管理工具管理 Node 与 OpenCode，便于回滚。
2. 密钥一律走环境变量，配置文件中不留明文。
3. 团队统一安装与配置步骤，写入项目 README。
4. 升级前先查看官方更新说明，评估影响。

## 常见问题

**Q1：Windows 上能用吗？**

能用，但强烈建议通过 WSL 获得完整终端体验，避免路径与权限问题。

**Q2：可以不装 Node 吗？**

部分平台提供独立安装方式，但 Node 生态是最稳定的路径。

**Q3：安装失败先查什么？**

先查网络与权限，这两类问题占安装失败的大多数。

## 本章总结

- 环境要求：macOS/Linux 体验最佳，需 Node、Git、编辑器。
- 安装方式：官方全局命令或包管理器，一条命令完成。
- 初始配置：Provider + 密钥环境变量 + 权限策略。
- 项目接入：已有项目直接启动，新项目先搭骨架，团队统一配置入库。
