# 开源模型

> 面向企业开发场景的开源模型选型与实践指南。重点讲解开源自部署的核心概念、主流选择与落地路径。不涉及安装细节。

---

## 为什么需要了解

开源模型是"数据可控、成本可预期、能力可定制"的代表，也是许多企业私有化 AI 的基础。理解开源生态（Llama、Qwen、DeepSeek、GLM 等）的能力边界与落地方式，是搭建完整模型池的必修课。

## 基本概念

### 什么是开源模型

开源模型指**权重公开**、可下载部署的语言模型。与闭源 API 模型相对，使用者拥有更大的自主权：

- 可部署在自己服务器上，数据不出境。
- 可针对业务做微调（Fine-tuning）。
- 无按量计费，成本为固定硬件投入。

### 核心权衡

| 维度 | 开源自部署 | 闭源 API |
| --- | --- | --- |
| 数据控制 | 完全自主 | 受厂商政策 |
| 成本结构 | 固定硬件成本 | 按量计费 |
| 定制能力 | 可微调 | 有限 |
| 上手成本 | 高（需部署运维） | 低 |
| 能力上限 | 通常低于同代旗舰闭源 | 通常更高 |

## 主流开源模型

### Llama（Meta）

- 开源模型的标杆系列，生态最活跃。
- 社区工具、量化、微调方案丰富。
- 适合作为通用开源基线。

### Qwen（阿里）

- 中文能力强，模型矩阵完整（多尺寸 + 多模态）。
- 国内团队中文场景的优选开源方案。

### DeepSeek（深度求索）

- 高性价比，推理能力强（R1 系列）。
- 开源权重支持本地部署，蒸馏小模型适合资源受限环境。

### GLM（智谱）

- 面向企业级应用，中文能力优秀。
- 提供开源权重与私有化方案。

### 其他活跃系列

- Mistral、Phi、InternLM、Yi 等，各有侧重，按场景评估。

## 核心能力

### 代码能力

- 中大型开源模型具备可靠的代码生成与理解能力。
- 小尺寸模型适合补全与简单任务，大尺寸模型胜任复杂开发。

### 推理能力

- 开源推理模型（如 R1 系蒸馏）在复杂问题上有可用表现。
- 受硬件限制，超大推理模型本地部署门槛较高。

### 多模态能力

- 部分开源系列提供视觉版本，支持截图、文档理解。
- 多模态开源模型的能力与闭源旗舰仍有差距。

### Tool Calling

- 主流开源模型支持函数调用，可作为 Agent 后端。
- 通过本地服务接入现有工作流。

## 企业实践

- **数据敏感场景**：本地部署，数据不出内网。
- **固定负载**：规模化后成本低于 API。
- **深度定制**：基于业务数据微调，形成专属模型。
- **混合部署**：敏感任务走本地，高质量任务走云端 API。

### 落地路径

1. **确定场景**：明确部署模型的用途与性能要求。
2. **评估硬件**：按模型尺寸估算显存/内存需求。
3. **选型测试**：用真实任务对比候选开源模型。
4. **部署服务**：接入推理框架，暴露统一接口。
5. **纳入网关**：与闭源模型一起路由，动态切换。

## 在 AI FullStack Workflow 中的位置

- 作为企业多模型池中的"可控与私有化"选项。
- 支撑数据合规、私有化部署与定制化场景。
- 与闭源模型通过网关统一路由，互补使用。

## 最佳实践

1. 先小规模验证，再规模化部署。
2. 按任务与硬件选择合适尺寸，避免"越大越好"。
3. 建立模型评测集，用真实任务对比选型。
4. 关注许可证条款，确认商用合规。

## 常见问题

**Q1：开源模型能替代闭源吗？**

部分场景可以，复杂任务与旗舰能力仍是闭源优势，建议混合使用。

**Q2：本地部署成本高吗？**

初始硬件投入较高，规模化后边际成本低，需按负载评估。

**Q3：如何选择开源模型？**

按任务复杂度、硬件预算、中文需求、生态成熟度综合评估。

**Q4：开源模型安全吗？**

模型本身风险可控，但部署、权限、数据隔离等工程环节需自己保障。

## 本章总结

- 开源模型以可控、低成本、可定制见长。
- 主流选择包括 Llama、Qwen、DeepSeek、GLM 等，各有侧重。
- 企业落地遵循"小规模验证 → 选型测试 → 部署 → 网关路由"路径。
- 与闭源 API 模型混合使用是常见的最佳实践。
