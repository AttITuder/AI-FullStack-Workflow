# Vision 与 Tool Calling

> 让 AI 从"只会读写文本"进化为"能看图和动手做事"。重点介绍在 AI Coding 中的工程用法，不深入底层原理。

---

## 为什么需要了解

大语言模型本身只处理文本，但真实的软件开发任务充满了"图像"与"行动"：UI 设计稿、报错截图、流程图表、执行命令、读写文件、调用接口。**Vision（视觉）让模型能看，Tool Calling（工具调用）让模型能做**，二者共同支撑了现代 AI Coding 工作流，也是 MCP、Agent 得以成立的基础。

## 基本概念

### Vision（视觉）

让模型理解图像输入的能力。底层是把图像编码为模型可处理的表示，对使用者而言，只需知道：**模型能接收图片，并返回基于图片的理解结果**。

### Tool Calling（工具调用）

让模型在推理过程中调用预定义函数/工具的能力。模型"决定"调用哪个工具、传什么参数，由执行环境真正执行，再把结果反馈给模型继续推理。

### MCP（Model Context Protocol）

MCP 是连接"模型"与"外部工具/数据源"的**统一标准协议**。它把各类工具（GitHub、数据库、文件系统、命令行）抽象为标准的资源与服务，模型通过 MCP 客户端即可统一访问。

### Function Calling（函数调用）

一种具体的工具调用机制：调用方预定义函数签名（含参数说明），模型在需要时返回"调用哪个函数 + 传什么参数"的结构化结果。

### Agent Tool（智能体工具）

在 Agent 架构中，工具是"可被模型自主调用的能力单元"。模型根据任务规划，按需组合多个工具完成多步骤目标。

## 核心能力

### Vision 能力拆解

| 能力 | 说明 | 开发场景 |
| --- | --- | --- |
| 图像理解 | 识别图中对象、文字、布局 | UI 截图分析 |
| OCR | 从图片提取文字 | 扫描件、报错图转文本 |
| UI 理解 | 理解界面结构、组件、层级 | 设计稿转代码 |
| 图片分析 | 视觉元素识别与描述 | 产品图、图表解读 |
| 设计稿分析 | 解析设计规范、尺寸、颜色 | 设计还原开发 |

### Tool Calling 能力拆解

| 能力 | 说明 | 开发场景 |
| --- | --- | --- |
| 函数调用 | 按需调用预定函数 | 工具链集成 |
| 命令执行 | 运行终端命令 | 构建、测试、部署 |
| 文件读写 | 读写项目文件 | 代码生成、重构 |
| 数据查询 | 访问数据库/接口 | 联调、排查 |
| MCP 接入 | 通过标准协议接外部工具 | 打通研发工具链 |

## 企业实践

### Vision 在 AI Coding 中的使用

**1. UI 设计稿转代码**

- 输入：设计稿截图（Figma 导出图、PNG）。
- 处理：模型识别布局、组件、样式。
- 输出：页面代码（Flutter / Android / Vue）。
- 工作流：设计稿 → Vision 解析 → 结构化描述 → Coding 模型生成 → 人工校验。

**2. 错误与截图排查**

- 把报错截图、界面异常图直接给模型，快速定位问题区域。
- 配合日志文本，综合判断根因。

**3. 文档与图表数字化**

- 架构图、流程图、手写草图转结构化说明，辅助生成文档或代码。

### Tool Calling 在 AI Coding 中的使用

**1. Agent 化开发**

- 模型读取代码库 → 规划任务 → 调用"读写文件/执行命令"工具 → 完成修改。
- 这是 OpenCode、Codex 等工具的工作方式。

**2. 构建与验证自动化**

- 模型生成代码后，自动执行构建、测试命令，根据结果迭代修复。

**3. 外部服务接入**

- 通过 MCP 让模型访问 GitHub、数据库、Jira 等，完成跨系统任务。

### 典型 AI Coding 工作流

```text
需求 → 模型读取代码库(文件工具)
     → 编写代码(生成)
     → 运行测试(命令工具)
     → 根据报错修正(Vision 看截图 + 文本分析)
     → 提交 MR(外部工具/MCP)
```

## 在 AI FullStack Workflow 中的位置

- **Vision**：支撑"设计稿转代码""错误排查"等可视化环节。
- **Tool Calling**：支撑"Agent 自主执行"，是 OpenCode / Codex 能力的根基。
- **MCP**：把 Tool Calling 标准化，让工作流可跨工具、跨厂商复用。
- 它们共同构成 `docs/08-mcp/`、`docs/11-agent/` 章节的认知前提。

## 最佳实践

1. **按需启用多模态**：只有任务涉及图像才用 Vision 模型，避免浪费。
2. **先给上下文再调工具**：让模型先理解项目，再执行修改。
3. **限制工具权限**：对 Agent 可用工具做白名单，降低风险。
4. **验证工具结果**：模型调用工具后，人对关键结果复核。
5. **工具描述写清楚**：函数/工具的说明越精确，模型调用越准确。

## 常见问题

**Q1：Vision 能直接生成完美代码吗？**

不能。设计稿转代码的产出需要人工校验布局与交互，AI 是加速器而非终结者。

**Q2：Tool Calling 与 MCP 有什么区别？**

Tool Calling 是"能力机制"，MCP 是"标准协议"。MCP 让工具调用标准化，避免各家自造接口。

**Q3：Agent 会乱执行命令吗？**

有风险。工程上通过权限限制、命令白名单、人工确认来规避。

**Q4：所有模型都支持 Vision 和 Tool Calling 吗？**

不是。选型时需确认模型能力清单（详见 `10-model-selection.md`）。

## 本章总结

- Vision 让模型能看图：设计稿转代码、截图排查、图表数字化。
- Tool Calling 让模型能做事：读文件、跑命令、接服务。
- MCP 把工具调用标准化，是 Agent 工作流的基础设施。
- 企业实践要点：按需启用、权限控制、结果复核、工具描述精确。
