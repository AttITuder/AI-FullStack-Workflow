# AI 辅助 Vue 开发

> 本文聚焦"AI 到底能在 Vue 开发里做什么、怎么用"，从具体场景出发，说明 AI 如何与 Prompt、Rules、MCP、Agent 配合，提升 Vue 开发效率。

---

## 1. AI 辅助 Vue 场景

### 1.1 页面生成

AI 把需求描述生成完整的 Vue 页面（模板 + 逻辑 + 样式 + 路由），并接入状态与数据。这是价值最高、最成熟的场景。

### 1.2 组件生成

AI 能生成可复用的基础组件与业务组件，保证接口（props / emits）、风格与项目一致。

### 1.3 UI 实现

AI 把设计稿或视觉描述还原为 Vue 模板与样式，处理布局、交互、响应式。

### 1.4 CSS 优化

AI 能帮助整理样式、抽取公共样式、修复样式冲突与性能问题（如过度选择器、布局抖动）。

### 1.5 状态管理

AI 辅助设计局部 / 全局状态划分与 Pinia store 结构，处理异步三态。

### 1.6 Debug

AI 结合控制台报错、日志与代码快速定位 Bug，给出根因假设与修复方案。

### 1.7 重构

AI 拆解过大组件、提取 composables、统一命名、规范化状态管理。遵循"先方案、后动手"。

## 2. AI 理解 Vue 项目

AI 生成 / 修改代码前，需要先"理解"当前项目。

### 2.1 理解维度

- **技术栈**：Vue3 还是 Vue2、TS 是否启用、UI 库、CSS 方案。
- **工程结构**：views / components / stores / api 的组织方式。
- **数据流**：数据从哪来（API / store）、到哪去（页面 / 组件）。
- **路由**：路由组织、懒加载、守卫。
- **风格**：既有组件的命名与写法。

### 2.2 让 AI 更好理解

- 提供目录结构、路由配置、关键组件、`package.json` 作为 Context。
- 保持命名与分层一致，降低理解成本。
- 用简洁注释说明组件 / 模块职责。
- 让 AI"复述"理解后再动手。

## 3. AI 辅助 Vue 架构设计

AI 可以作为架构方案的"参谋"。

### 3.1 给出可选方案

针对项目规模，AI 给出分层、状态管理、组件组织的利弊对比，而不是武断选一个方案。

### 3.2 分析现状与缺口

AI 分析当前结构的职责是否清晰、组件是否过度膨胀、状态管理是否合理，指出重构点。

### 3.3 重要原则

- **不绑定单一技术方案**为唯一方案（状态管理、UI 库、CSS 方案都取决于项目）。
- **人拍板**：架构是团队决策，AI 只提供分析建议。
- **先方案后动手**：重大变更须人工确认。

## 4. AI 辅助前端问题定位

AI 在 Debug 场景的价值在于"快速缩小范围"。

### 4.1 输入组织

提供完整信息：报错信息、相关代码、复现步骤、浏览器与网络请求。信息越全定位越快。

### 4.2 输出形式

- 问题类型判断（响应式、生命周期、异步、类型、样式）。
- 根因候选与依据。
- 修复方案与验证方式。
- 需要补充的信息（信息不足时主动询问）。

### 4.3 注意点

- 让 AI"先定位根因，再修复"，避免盲改。
- 结合浏览器 DevTools 与网络面板信息。
- 修复后通过构建 / lint / 测试验证，必要时补用例防回归。

## 5. AI + Prompt

Prompt 是把需求翻译成任务的关键（见 `docs/10-prompts/` 与 `prompts/vue/`）。

### 5.1 好 Prompt 的要素

- 角色设定（资深 Vue 前端工程师）。
- 技术栈约束（Vue3 / Composition API / TS / Vite / Pinia / UI 库 / CSS 方案）。
- 明确任务与范围。
- 输出要求与验收清单。
- 用 `【】` 占位符实现可复用。

### 5.2 Context 的重要性

好的生成依赖充分的 Context：相关代码、接口文档、路由结构、既有组件风格。Context 不足会导致 AI 产出偏离现状。

### 5.3 Prompt 与 Agent 的关系

Agent 提供"身份与纪律"，Prompt 提供"本次任务"。两者配合：Agent 决定"你是谁、怎么工作"，Prompt 决定"这次干什么"。

## 6. AI + Rules

Rules 让 AI 产出"符合团队预期"的代码（见 `docs/09-rules/` 与 `rules/vue/`）。

### 6.1 Rules 的作用

- 统一 Vue3 / Composition API 写法规范。
- 约束类型（TS）、组件命名与结构、props / emits。
- 状态管理使用方式。
- 作为生成与 Review 的验收标准。

### 6.2 让 AI 遵守 Rules 的方法

- 在 Agent 系统提示词中引用 Rules。
- 在 Prompt 中要求对照 Rules 生成。
- 在 Review 阶段让 AI 按 Rules 逐项核对。

### 6.3 高质量 Rules 的特点

可执行、可检查、不模糊。没有 Rules，AI 输出风格千差万别。

## 7. AI + MCP

MCP 让 AI 触达外部工具与数据，增强 Vue 开发流程（见 `docs/08-mcp/` 与 `mcp/`）。

### 7.1 MCP 在 Vue 开发中的价值

- **Figma**：读取设计稿数据，辅助 UI / 组件还原。
- **文档 / 接口**：规范与接口文档作为生成 Context。
- **GitHub / Git**：分支与变更管理、辅助 Review。
- **数据 / 数据库**：联调数据参考。

### 7.2 MCP 与 Vue 的结合点

- UI 还原：Figma MCP 提供设计数据 → 生成对应组件。
- 信息获取：接口 / 规范文档 MCP → 作为 Prompt Context。
- 持续验证：构建 / CI MCP 提供反馈 → 迭代代码。

## 8. 企业 Vue 项目 AI Workflow

在企业项目中，AI 的价值不止于"单点提效"，而是整条研发流水线。

```text
需求管理 → 任务拆解 → 代码生成 → 测试 → Review → 发布（Release）
```

### 8.1 统一资产

- 团队统一的 Prompt 库（`prompts/vue/`）。
- 统一的 Rules 库（`rules/vue/`）。
- 可复用的 Agent（`agents/` 中的架构 / Review / Test）。
- 统一的 MCP 配置（`mcp/`）。

### 8.2 团队协作要点

- 产出风格一致、质量可预期。
- 交接成本降低：新人加载同一套资产即可上手。
- 规范可传承：最佳实践沉淀为资产。

### 8.3 质量闭环

- Code Review 由 AI 辅助 + 人工拍板。
- 构建（Vite）与测试体系（单元 / 组件 / E2E）建立。
- 安全与合规红线约束（见 `05-best-practice.md`）。

### 8.4 发布链路

- 版本管理、构建产物、环境变量（dev / prod）、部署流程在 Rules 与流程中沉淀。
- AI 辅助生成构建配置与发布检查项，但关键发布决定由人掌控。

### 8.5 落地路径

从"个人用 AI 提效"起步，逐步沉淀团队资产，最终形成稳定、可复现的企业级 Vue AI 研发流水线。

## 总结

- AI 在 Vue 开发中的价值覆盖页面生成、组件生成、UI 实现、CSS 优化、状态管理、Debug、重构。
- Prompt、Rules、MCP、Agent 各司其职：Prompt 传递任务、Rules 约束产出、MCP 连接能力、Agent 负责执行纪律。
- 企业落地靠统一资产沉淀与测试 / Review / 发布的质量闭环。
