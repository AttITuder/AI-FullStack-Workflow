# Vue 开发 Workflow

> 本文是 Vue + AI 的"操作手册"：针对研发中的每一类典型任务，给出可复现的工作流。最终把所有流程汇入一条统一的 需求 → Prompt → Rules → Agent → Vue 代码 → 测试 → Review 链路。

---

## 1. 新页面开发 Workflow

新页面开发是最常见的任务，流程目标是在明确边界内产出可验证的代码。

```text
页面需求
  ↓
Context（阅读相关模块，理解现状）
  ↓
Prompt（本次页面目标 + 技术栈约束）
  ↓
Rules（编码规范）
  ↓
Agent（规划 → 拆分子任务）
  ↓
生成页面组件 + 路由
  ↓
构建 / lint / 测试验证
  ↓
Review
```

关键控制点：

1. **先读现状再写**：理解相关页面、组件、接口的既有实现与风格，避免风格漂移。
2. **同步处理路由**：新生页面的路由注册、懒加载、守卫纳入。
3. **明确验收标准**：可编译、组件结构合理、行为与交互符合需求。

这一流程是后续各类具体 Workflow 的共同骨架。

## 2. 组件开发 Workflow

组件是 Vue 的核心复用单元，开发需保证接口清晰、可复用。

```text
组件需求（复用范围 / 接口）
  ↓
明确组件层级（基础 / 业务 / 页面）
  ↓
Prompt：设计 props / emits / 职责
  ↓
生成组件（模板 + 逻辑 + 样式）
  ↓
接入使用处，构建 + 测试验证
  ↓
Review 接口与风格
```

关键点：

- 单一职责，一个组件只做一件事。
- `props` 定义清晰，`emits` 明确事件，避免组件间直接操作对方状态。
- 复用度高的逻辑提取到 composables。
- 样式符合项目 CSS 方案，保持命名规范。

## 3. API 接入 Workflow

接口接入涉及数据层与页面 / 状态的联动。

```text
拿到接口文档（请求 / 响应结构）
  ↓
确认统一 API 客户端（axios / fetch）
  ↓
生成 API 方法 + TypeScript 类型
  ↓
在 Service / Repository 组织调用
  ↓
在页面 / store 调用，处理加载 / 成功 / 失败
  ↓
构建 + 联调验证
```

关键点：

- **复用统一客户端与拦截器**，不散落新建实例（对应 `rules` 约束）。
- 类型定义与后端结构对应，避免 `any` 泛滥。
- 错误处理完整：网络异常、超时、业务错误码都应有反馈。
- 通过 Vite 代理或环境变量管理 BaseURL，不硬编码。

## 4. 状态管理 Workflow

状态管理需先想清楚"什么状态、放哪、怎么更新"再写。

```text
明确状态粒度（组件局部 / 全局）
  ↓
局部状态用 ref / reactive；全局状态用 Pinia
  ↓
设计 state / getters / actions
  ↓
在组件中读取与触发，处理好异步三态
  ↓
构建 + 测试验证
```

通用异步三态：`loading`、`data`、`error` 三字段。

```ts
const list = ref([])
const loading = ref(false)
const error = ref('')
```

建议：状态流转先"画清楚"让 AI 生成，再由人校验正确性。全局状态只在跨组件真正共享时才用。

## 5. UI 还原 Workflow

UI 还原涉及把设计稿或视觉描述变成 Vue 模板与样式。

```text
拿到设计稿 / 视觉描述
  ↓
确认技术栈（UI 组件库 / CSS 方案）
  ↓
提供尺寸、颜色、间距、交互作为 Context
  ↓
生成模板 + 样式
  ↓
视觉比对调整，构建验证
```

关键点：

- 复用项目 UI 组件库，保持界面风格一致。
- 样式命名与方案遵循项目约定（Tailwind / SCSS / CSS Modules 等）。
- 响应式与不同屏幕适配到位。
- 可结合 MCP（Figma）读取设计稿数据提高还原度。

## 6. Bug 修复 Workflow

修复 Bug 的准则：**先定位根因，再修复**，避免"盲改碰运气"。

```text
复现 / 收集控制台报错
  ↓
定位根因：响应式？生命周期？异步？类型？
  ↓
先复现，再最小化定位（必要时加日志）
  ↓
修复 → 构建 / lint 验证 → 回归相关功能
  ↓
补充说明与测试
```

常见 Bug 类型：

- 响应式失效（响应式数据被解构 / 赋值丢失响应性）。
- 生命周期钩子时机错误（`watch` / `onMounted` 顺序）。
- 异步未更新状态或重复请求。
- TypeScript 类型不匹配。

## 7. 性能优化 Workflow

性能优化需要先测量、再定位、后优化。

```text
明确性能目标（首屏 / 交互 / 渲染）
  ↓
用工具测量（浏览器 DevTools / Lighthouse）
  ↓
定位瓶颈（包体积 / 渲染次数 / 请求）
  ↓
针对性优化，构建验证并复测
```

常见优化手段：

- 路由与组件懒加载（`() => import(...)`），减小首屏包体积。
- 合理使用计算属性（`computed`）避免多余渲染。
- 列表用 `key`、虚拟滚动处理大列表。
- 请求并发 / 缓存 / 分页优化。
- 代码拆分与 Tree-shaking。

原则：**性能优化是测量驱动的**，AI 应基于测量数据给建议，而不是空谈。

## 8. 重构 Workflow

重构的前提是**先给方案、确认后再动手**。

```text
识别重构目标（过大组件 / 重复逻辑 / 状态混乱）
  ↓
Agent 给出重构方案（拆什么、怎么拆、影响范围）
  ↓
人工确认方案
  ↓
小步重构，每步构建 / lint / 测试验证
  ↓
测试回归，确认行为不变
```

安全重构要点：

- 每次只做一类重构，避免大爆炸式改动。
- 优先行为不变：重构不改功能，只改结构。
- 依托测试保证行为可验证。
- 重构后跑 lint 与单元测试。

## 9. Code Review Workflow

AI 辅助 Code Review 能降低人工审查成本，但与人工判断结合。

```text
提交变更
  ↓
Agent 对照 rules/vue 逐项审查
  ↓
输出结构化意见（组件 / 类型 / 状态 / 错误处理 / 性能 / 安全）
  ↓
人工复核，采纳合理意见
```

审查维度：

- 组件命名、结构、props / emits 是否清晰。
- 状态管理是否合理（局部 / 全局）。
- TypeScript 类型是否严谨。
- 是否复用统一封装（API、样式、组件）。
- 性能隐患与安全风险（敏感信息、注入）。

`05-best-practice.md` 有更系统的审查清单。

## 10. Prompt + Rules + Agent Workflow

把前面所有流程汇总为统一执行链。它回答了"**Vue + AI 到底怎么跑通一次开发**"。

```text
需求
  ↓
Prompt（把需求翻译成明确、带约束的任务）
  ↓
Rules（加载编码规范，作为生成与验收依据）
  ↓
Agent（进入执行闭环，理解项目后动手）
  ↓
Vue 代码（分模块产出，遵循分层）
  ↓
测试（单元 / 组件 / lint / build）
  ↓
Review（对照 Rules 结构化审查）
```

各环节的职责：

- **Prompt**：负责"意图"，把模糊需求变成可执行任务，用 `【】` 占位符复用模板。
- **Rules**：负责"纪律"，约束生成与验收标准，保证风格一致。
- **Agent**：负责"执行"，理解 Vue 项目、拆解任务、生成 / 自检 / 交付。
- **Model**：负责"推理与生成"，是能力底座。
- **MCP / Tools**：负责"触达外部"，连接接口、设计稿等。
- **测试与 Review**：负责"验收"，保证质量闭环。

这一条链就是 `01-overview.md` 中 Vue AI Workflow 的可执行版本。把每一步都标准化、可复用，Vue 开发的效率与质量就能从"碰运气"变成"可复制"。

## 总结

- 新页面、组件、API、状态管理、UI 还原、Bug、性能、重构、Review，每类任务都有明确可复现的 Workflow。
- 统一原则：**先读后写、先方案后动手、可验证、遵循 Rules、重视组件与路由**。
- 所有流程最终汇入 需求 → Prompt → Rules → Agent → Vue 代码 → 测试 → Review 的统一链路。
- 项目 `agents/` 中架构 / Review / Test 等 Agent 是这套工作流的可复用支撑。
