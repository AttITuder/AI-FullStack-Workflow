# Prompt Best Practice

> 本章节核心方法文章。单个团队的 Prompt 能力差距，不在于谁更会写金句，而在于是否把 Prompt 当作工程资产来管理。本文给出二十条实践原则，覆盖从编写、验证到维护、演进的完整生命周期。

---

## 为什么需要了解

个人用 Prompt 靠手感，团队用 Prompt 靠制度。没有管理制度的 Prompt 库会迅速腐化：重复、过期、无人敢用、无人维护。本文的原则来自一个朴素的目标——**让团队成员敢于直接复制任何一个库里的 Prompt 用于生产任务**。要做到这一点，每个资产都必须经过编写规范、实测验证、持续维护三道关口。

## 一、资产管理原则

## 1. 资产化：从一次性指令到团队资产

判断一条 Prompt 是否值得沉淀，看两个信号：

- **复用信号**：同类任务你已经手写过第二次。
- **质量信号**：这条 Prompt 的产出经过了验证且效果好。

满足其一就沉淀。反过来说，一次性的临时探索不需要进库——库里只放验证过的东西，这是整个体系信用的基础。

## 2. 单一事实源

每条 Prompt 只在一个地方维护：

```text
prompts/          ← Prompt 资产的唯一存放地
docs/10-prompts/  ← 方法论，不含可复制的 Prompt 正文
```

文档章节讲解方法时可以引用资产做案例，但不复制正文；其他文档需要某条 Prompt 时给路径而不是粘贴内容。两处维护同一份内容的结果必然是版本漂移。

## 3. 模板先行

新 Prompt 从项目标准结构出发，不从空白文件开始：

- 结构以 `docs/00-roadmap/writing-style.md` 第 6 节为准：**适用场景、使用说明、期望输出、验收清单**四部分。
- Prompt 本体放围栏代码块内，语言标识 `text`。

模板的价值不在省事，而在**降低使用者的认知成本**——所有资产长一个样，找到就能直接用。

## 4. 占位符规范

所有可变内容统一使用全角括号占位符：

```text
请生成【页面名称】页面，调用【接口地址】接口。
```

规则：

- 占位符内是**名词性描述**，不是示例值：【页面名称】而非【登录页】。
- 同一 Prompt 中同一概念用同一个占位符名。
- 使用说明中交代如何替换占位符。

## 二、组织与命名

## 5. 目录按双维度组织

本项目 `prompts/` 按技术栈与场景两个维度划分：

- 技术栈维度：android / dart / flutter / java / kotlin / vue——面向特定平台的开发任务。
- 场景维度：architecture / product / refactor / review / test / ui——跨技术栈的通用任务。

归属判断很简单：换一个技术栈这条 Prompt 还成立吗？成立进场景维度，不成立进对应技术栈目录。

## 6. 文件命名见名知义

文件名 = 任务动作，不加日期、作者、版本号：

```text
generate_page.md    ✓ 页面生成
fix_crash.md        ✓ 崩溃修复
prompt_v2_final.md  ✗ 版本信息属于 git，不属于文件名
```

## 7. 一个文件一个 Prompt

禁止把多个 Prompt 堆在一个"大全"文件里。独立成文才能独立引用、独立维护、独立废弃。

## 三、编写质量

## 8. 四要素齐全才算完成

适用场景、使用说明、期望输出、验收清单缺一不可：

- **适用场景**：什么情况下该用这条 Prompt，边界在哪。
- **使用说明**：占位符怎么替换、需要按项目调整什么。
- **期望输出**：交付物的形态与结构。
- **验收清单**：逐项核对产出质量的检查表。

对照 `prompts/flutter/generate_page.md` 可以看到完整的落地形态。

## 9. 写"为什么"，不只是"是什么"

高质量的 Prompt 资产会交代关键约束背后的原因：

```text
网络层走统一封装（避免散落的 Dio 实例导致拦截器配置不一致）。
```

原因让使用者能判断 Prompt 在新场景下是否依然适用——约束可迁移的前提是理解动机。

## 10. 保持最小完备

定期审视已有资产：删除模型常识能补全的描述、删除从未生效的约束、合并重复段落。臃肿的 Prompt 不仅浪费 Token，还会稀释关键信息的权重。

## 四、验证与迭代

## 11. 实测通过才能入库

入库前必须在真实项目中完整跑一遍：

1. 按使用说明替换占位符执行。
2. 对照验收清单逐项核对产出。
3. 不达标就修改 Prompt 重测，直到稳定通过。

未经验证的 Prompt 标记为草稿状态或放在规划清单里，不进入正式资产序列。

## 12. 验收清单来自真实失败

验收清单不是拍脑袋写的合规声明，最好的来源是**实际踩过的坑**：生成代码忘记注册路由，清单就加一条"路由注册正确"。每条验收项背后都应该有一个它防住的失败案例。

## 13. 使用反馈驱动迭代

资产入库只是起点。建立轻量的反馈通道：使用中发现 Prompt 不好用，直接改并提交，commit message 说明改了什么、为什么。小步快改优于攒大招重写。

## 14. 问题上升机制

同一个问题在 Prompt 层面反复补救时，就该上升到 Rules 层面长期生效：

```text
现象：多条 Prompt 都要写"路由记得注册"
对策：把"新增页面必须注册路由"写入 rules/flutter/，
     之后各 Prompt 引用规则即可，不再重复交代
```

这正是 Prompt 层与 Rules 层的分工在维护期的体现——详见 `docs/09-rules/01-overview.md` 第 4 节。

## 五、演进与协作

## 15. 向 Agent 配置升级

当一个 Prompt 的使用频率高到"每次都手动找来粘贴"，考虑升级为 Agent 的一部分：

```text
prompts/flutter/generate_page.md     ← 手动复制的资产
agents/flutter-agent/                ← 自动生效的配置
```

升级判断标准：高频 + 稳定 + 无需按次定制。三者同时满足才升级——还需要按次调整内容的 Prompt 留在 prompts/ 更灵活。

## 16. 版本管理走 Git

Prompt 资产与代码同库同流程管理：

- 变更走 commit，message 说清改动动机（遵循项目的 Git 提交规范）。
- 重要调整开 PR 让团队成员 Review。
- 回溯历史靠 git log，不在文件里写更新记录。

## 17. 废弃有仪式

过时的 Prompt 明确处理而不是留在原地腐烂：

- 技术栈演进导致失效（如框架大版本迁移）：删除或归档，README 规划清单同步更新。
- 被 Agent 配置取代：原文件标注去向或移除。
- 目录 README 的"现有模板"表格与实际文件保持一致——`prompts/flutter/README.md` 的表格就是范本。

## 18. 团队评审聚焦三点

Review 别人的 Prompt 资产时看三件事：

1. **可复现**：换个新人按使用说明操作，能否得到同样质量的产出？
2. **验收可核对**：清单是否具体到能打勾，而不是"代码质量良好"这类空话？
3. **位置正确**：该进 Rules 的内容有没有错放进 Prompt？

## 六、安全与度量

## 19. 安全红线

Prompt 资产是会被大量复制的文本，入库前检查：

- 不包含真实密钥、密码、内网地址等敏感信息，一律用占位符替代。
- 不硬编码仅限特定客户 / 特定环境的业务数据。
- 涉及外部服务的 Prompt 在使用说明中提示数据出境 / 脱敏要求。

## 20. 用结果度量价值

Prompt 库的价值最终体现在研发指标上，建议观察三个信号：

- **一次通过率**：同类任务不经返工直接达标的比例是否上升。
- **上手速度**：新人借助 Prompt 库独立完成首个功能的时间是否缩短。
- **返工类型收敛**：反复出现的返工原因是否逐步转化为 Rules 或验收清单项。

度量不需要精密系统，阶段复盘时对照这三问即可。

## 反模式速查

| 反模式 | 后果 | 替代做法 |
| --- | --- | --- |
| Prompt 大全文件 | 无法独立引用与维护 | 一个文件一个 Prompt |
| 未实测直接入库 | 库的信用破产 | 实测通过才入库 |
| 复制正文到处粘贴 | 版本漂移 | 引用路径 |
| 验收清单写空话 | 无法核对 | 来自真实失败的检查项 |
| 文件名带 v2/final | 版本混乱 | git 管理版本 |
| 该进 Rules 的塞进 Prompt | 每条 Prompt 重复交代 | 问题上升机制 |

## 本章总结

- 沉淀标准：复用或质量信号触发资产化，库里只放实测通过的 Prompt。
- 组织原则：双维度目录、见名知义命名、一个文件一个 Prompt、单一事实源。
- 编写质量：四要素齐全、交代约束动机、保持最小完备、占位符统一 `【】`。
- 迭代机制：真实失败驱动验收清单、使用反馈小步改进、反复问题上升为 Rules。
- 演进路径：高频稳定的 Prompt 升级为 Agent 配置；版本走 Git；废弃有仪式。
- 安全底线：敏感信息一律占位符化。
- 价值度量：一次通过率、上手速度、返工类型收敛三个信号。
