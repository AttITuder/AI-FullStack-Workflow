# Claude Code 最佳实践

> 面向长期维护项目的实战经验总结。围绕 Prompt 设计、Context 管理、Rules 使用、MCP 集成、大型项目、团队协作与常见错误，沉淀可直接落地的做法。

---

## 为什么需要了解

Claude Code 是"任务委派型"Agent，产出质量高度依赖委派方式。本文把实战中验证过的经验固化为最佳实践，帮助团队稳定获得高质量产出。

## 1. Prompt 设计

### 结构化委派

- **说清背景**：项目类型、技术栈、现有架构。
- **说清任务**：要做什么，范围与边界。
- **说清约束**：规范、风格、禁止事项。
- **说清输出**：期望文件、结构、验收标准。

### 提供示例

- 给出"对的样子"（已有代码、期望风格），比纯文字描述更有效。
- 示例越接近目标场景，产出越准确。

### 分步委派

- 大任务拆成小任务逐个委派，避免一次要求过多。
- 每步确认后再进入下一步。

### 用清单约束

- 委派末尾附验收清单，让 Agent 自检后交付。

## 2. Context 管理

### 提供足够但不过量的上下文

- 只给任务相关的文件与信息。
- 大型项目优先用文件引用与检索，而非全量塞入。

### 明确项目上下文

- 让 Agent 先读关键文件（入口、配置、数据模型）再动手。
- 把团队 Rules 纳入上下文，约束产出风格。

### 会话聚焦

- 一次会话聚焦一个任务，避免上下文污染。
- 完成一个任务后开启新会话，保持上下文干净。

## 3. Rules 使用

### 规则前置

- 编码规范、命名约定、架构约束在委派时明确。
- 参考 `rules/` 目录，把团队规范纳入上下文。

### 可执行可检查

- 规则要可执行、可检查，避免模糊表述。
- 用验收清单检查 Agent 是否遵守。

### 持续维护

- 根据产出反馈修订规则。
- 规则与 Prompt、Agent 配置保持同步。

## 4. MCP 集成

### 选择需要的 MCP

- 按团队工具链选择：GitHub、数据库、设计稿、文档平台。
- 参考 `mcp/` 目录与 `docs/08-mcp/` 章节。

### 配置要点

- 每个 MCP 明确用途与权限边界。
- 密钥走环境变量，配置入库。
- 无用的 MCP 不接入，减少上下文与风险面。

### 使用原则

- MCP 是"连接器"，让 Agent 触达真实工具与数据。
- 对外部系统的写操作保持谨慎，必要时人工确认。

## 5. 大型项目实践

### 分而治之

- 把大型任务拆成可独立完成的子任务。
- 一次处理一个模块，保持上下文可控。

### 善用检索

- 用检索/文件引用定位相关代码，避免全量读库。
- 让 Agent 基于真实代码做决策。

### 维护模块文档

- 为关键模块维护简短说明（用途、结构、约定）。
- Agent 可快速理解模块，产出更贴合现状。

### 渐进集成

- 分阶段生成与验证，避免一次大改无法回滚。

## 6. 团队协作

### 统一配置资产

- Rules、Prompt、Agent 配置纳入版本库。
- 新成员按 README 一键配置，体验一致。

### 规范落地

- 团队 Rules 前置到 AI 产出环节，而非事后补救。
- 建立"AI 产出 → 自动化检查 → 人工审查"的三道防线。

### 知识回流

- 每次成功实践沉淀到知识库。
- 让团队 AI 能力随项目一起成长。

### 安全与合规

- 敏感数据走本地或合规方案。
- 密钥统一管理，定期轮换。
- 记录 AI 执行行为，保留审计痕迹。

## 7. 常见错误

### 错误一：不提供上下文

让 Agent 凭空猜项目结构，产出牛头不对马嘴。

**修正**：先让 Agent 读代码库，再给任务。

### 错误二：一次委派太多

让 Agent 一次性完成巨大任务，质量失控。

**修正**：拆成小任务，逐步确认。

### 错误三：盲目信任输出

不经验证就合入 Agent 代码。

**修正**：测试 + 审查双保险。

### 错误四：不沉淀规则

每次靠人肉纠正，团队没有积累。

**修正**：把教训写进 Rules 与 Prompt。

### 错误五：上下文塞满

把整个仓库塞给 Agent，成本高效果差。

**修正**：检索 + 文件引用，按需加载。

### 错误六：密钥硬编码

把 API Key 写进配置提交仓库。

**修正**：环境变量 + 密钥管理。

### 错误七：忽略权限控制

让 Agent 拥有过大的命令权限。

**修正**：最小权限 + 命令白名单。

## 总结

- Prompt 讲究"背景、任务、约束、输出"四要素 + 示例 + 清单。
- Context 提供"足够但不过量"，会话聚焦单一任务。
- Rules 前置让 Agent 产出符合团队标准。
- MCP 按需接入，控制权限与风险面。
- 大型项目分而治之、善用检索、渐进集成。
- 团队协作统一配置资产、规范落地、知识回流。
- 避开常见错误，用工程手段保证产出质量。
