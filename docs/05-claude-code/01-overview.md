# Claude Code 概述

> 定位：不是普通产品教程，而是 AI Coding Workflow 知识库。目标读者：Android 开发者、Flutter 开发者、全栈开发者、企业研发人员。

---

## 1. Claude Code 是什么

### 定位

Claude Code 是 Anthropic 推出的 **AI Coding Agent**，以终端为主要交互方式，深度绑定 Claude 模型，把"模型理解代码库并自主执行工程任务"的能力融入日常开发流程。

它不是聊天机器人，而是能在真实项目中"干活"的 Agent：读取代码、规划任务、修改文件、运行命令、验证结果。

### Agent Coding 概念

Coding Agent 是具备以下能力的 AI 系统：

- **理解**：读取并理解项目结构与业务逻辑。
- **规划**：把任务拆解为可执行步骤。
- **执行**：生成与修改代码，调用工具。
- **验证**：运行测试，根据结果迭代修复。

Claude Code 是这一概念的产品化落地，特点是与 Claude 模型深度绑定，强调开箱即用的终端协作体验。

### 与普通聊天式 AI 的区别

| 维度 | 聊天式 AI | Claude Code |
| --- | --- | --- |
| 交互 | 一问一答 | 任务委派 |
| 上下文 | 会话文本 | 代码库 + 环境 |
| 执行 | 只输出文本 | 修改代码、运行命令 |
| 闭环 | 人落地结果 | Agent 自主闭环 |
| 产出 | 建议 | 可交付的改动 |

## 2. Claude Code 发展背景

### Claude 模型发展

Anthropic 的 Claude 模型在代码与长上下文场景逐步建立口碑：

- 早期模型验证了对话与写作能力。
- 后续版本强化代码生成、长上下文与工具调用。
- 代码质量与长文档理解成为标志性优势。

模型的演进为"Agent 化"提供了能力基础：只有足够强的理解与执行能力，才能承担自主编码任务。

### AI Coding Agent 演进

AI 编程经历了"补全 → 对话 → Agent"三代：

1. **补全时代**：行内代码补全，人主导。
2. **对话时代**：对话生成代码，结果需人手动落地。
3. **Agent 时代**：自主读取代码库、规划任务、执行修改、验证结果。

Claude Code 属于 Agent 时代的产品，把 AI 从"建议者"变成"执行者"，与 OpenCode、Codex 一起代表 AI Coding 的主流方向。

## 3. Claude Code 核心能力

### 项目理解

- 读取项目结构、技术栈与业务逻辑。
- 理解既有代码意图与约束。

### 代码生成

- 根据需求生成高质量代码，遵循常见架构约定。
- 在长上下文下保持产出一致性。

### 多文件修改

- 一次任务可修改多个文件，保持改动一致。
- 理解跨文件依赖关系。

### 重构

- 结构优化、命名规范、重复代码消除。
- 在不改变行为的前提下改善可维护性。

### 测试

- 生成单元测试、边界用例、集成测试。
- 辅助定位测试失败原因。

### Review

- 检查规范、安全、性能与逻辑问题。
- 输出结构化审查意见，供人工复核。

## 4. Claude Code 在 AI FullStack Workflow 中的位置

在完整工作流中，Claude Code 承担 **Agent（编码执行）** 的角色：

```text
需求
 ↓
分析
 ↓
规划
 ↓
Agent
 ↓
Coding
 ↓
Review
```

- **需求**：业务需求输入。
- **分析**：理解需求与现状。
- **规划**：拆解任务，确定方案。
- **Agent**：Claude Code 承担核心编码执行，终端内自主完成。
- **Coding**：生成与修改代码，可多文件协作。
- **Review**：AI 自检 + 人工审查，确认后合并。

在知识库层面，Claude Code 章节处于 Milestone 3（AI Coding 工具），与 OpenCode（本地开源）、Codex（云端）形成互补矩阵。

## 5. Claude Code 与其它工具区别

### 与 OpenCode 的区别

| 维度 | OpenCode | Claude Code |
| --- | --- | --- |
| 模型绑定 | 多 Provider 可配 | 深度绑定 Claude |
| 开源性 | 完全开源 | 部分开源 |
| 适用 | 灵活配置、定制 | 开箱即用的终端体验 |

### 与 Codex 的区别

| 维度 | Codex | Claude Code |
| --- | --- | --- |
| 运行环境 | 云端沙盒 | 本地终端 |
| 模型体系 | OpenAI | Claude |
| 适用 | 云端批量任务 | 本地终端工作流 |

### 与 Cursor 的区别

| 维度 | Cursor | Claude Code |
| --- | --- | --- |
| 形态 | IDE | 终端 Agent |
| 自主程度 | 人主导 | Agent 自主 |
| 适用 | 编辑器集成 | 终端工作流 |

### 与 CodeBuddy 的区别

| 维度 | CodeBuddy | Claude Code |
| --- | --- | --- |
| 生态 | 本土工具链 | 国际化生态 |
| 形态 | 集成式助手 | 终端 Agent |

### 与 Pi Agent 的区别

| 维度 | Pi Agent | Claude Code |
| --- | --- | --- |
| 定位 | 低门槛智能体 | 工程级 Coding Agent |
| 复杂度 | 入门轻量 | 深度任务执行 |

**选型结论**：追求开箱即用的终端 Agent 体验选 Claude Code，追求模型可换选 OpenCode，追求云端执行选 Codex。

## 6. 适合场景

- **Flutter 开发**：多文件页面生成、状态管理、重构（配合 `docs/12-flutter/`）。
- **Android 开发**：Kotlin 代码、Compose UI、构建（配合 `docs/13-android/`）。
- **Backend 开发**：服务端代码、接口实现、数据模型。
- **Web 开发**：前端页面、组件、状态管理。
- **大型项目**：长上下文理解大型代码库。
- **代码审查**：长文档与代码审查能力突出。
- **企业研发**：规则约束下产出高质量代码。

## 7. 不适合场景

- **多模型自由切换需求**：深度绑定 Claude，难以替换模型。
- **零配置要求**：需要一定初始配置与终端基础。
- **强 IDE 图形依赖**：终端形态对部分开发者有门槛。
- **完全云端托管**：本地运行，不适合云端隔离需求。
- **纯视觉任务**：编码为主，强视觉任务应由多模态模型承担。

- Claude Code 是 Anthropic 的终端 AI Coding Agent，深度绑定 Claude 模型。
- 核心能力覆盖项目理解、代码生成、多文件修改、重构、测试与审查。
