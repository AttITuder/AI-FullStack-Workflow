# Claude Code FAQ

> Claude Code 使用中的常见问题整理。按安装、模型、账号、上下文、代码质量、Agent、MCP、企业使用、成本优化、故障排查分类。

---

## 安装问题

## Q1: Claude Code 安装失败怎么办？

### A

先按顺序排查：

1. **权限问题**：配置 npm 全局目录为用户可写路径，避免 `sudo`。
2. **网络问题**：检查代理与镜像配置后重试。
3. **环境问题**：确认 Node 版本符合要求，清理缓存重装。

## Q2: 命令找不到怎么办？

### A

- 确认安装成功且命令在 `PATH` 中。
- 重开终端或重载 shell 配置。
- Windows 建议使用 WSL。

## Q3: 登录后仍未生效怎么办？

### A

- 确认凭据环境变量正确导出。
- 重启会话让配置生效。
- 查看日志定位鉴权问题。

## 模型问题

## Q4: 如何选择 Claude 的不同型号？

### A

- 常规编码用均衡/代码模型。
- 疑难推理用推理模型。
- 按任务复杂度路由，避免一刀切。

## Q5: 可以用其他模型替代 Claude 吗？

### A

Claude Code 深度绑定 Claude，但团队可通过网关将其他模型纳入统一工作流，按任务路由。

## Q6: 不同模型产出风格不一致怎么办？

### A

通过团队 Rules 统一约束产出风格，让任何模型都按同一标准输出。

## 账号问题

## Q7: 需要什么账号才能用 Claude Code？

### A

- 需要 Anthropic 账号或对应订阅。
- 具体以官方说明为准。

## Q8: 登录失败或鉴权报错怎么办？

### A

- 重新登录账号。
- 检查凭据环境变量。
- 确认账号具备对应权限。

## Q9: 账号共享给团队安全吗？

### A

不建议共享。建议为成员分配独立账号，便于管理与审计。

## 上下文问题

## Q10: Claude Code 不了解我的项目怎么办？

### A

- 让 Agent 先读关键文件（入口、配置、数据模型）。
- 提供项目结构说明与技术栈信息。
- 把 Rules 与模块文档纳入上下文。

## Q11: 上下文太大效果变差怎么办？

### A

- 只加载任务相关文件，避免噪声。
- 优先使用文件引用与检索。
- 会话聚焦单一任务。

## Q12: 如何让 Agent 记住项目约定？

### A

- 把约定写成 Rules 与模块文档。
- 每次委派时引用或自动加载。
- 通过 Agent 配置固化常用约定。

## 代码质量问题

## Q13: 生成的代码不靠谱怎么办？

### A

- 先让 Agent 给方案，人确认后再生成。
- 用测试验证行为，不盲信输出。
- 审查安全、性能与边界条件。

## Q14: 如何提高生成代码准确性？

### A

- 提供现有代码示例作为风格参照。
- 明确技术栈、架构与约束。
- 用验收清单约束输出。

## Q15: 代码引入了安全隐患怎么办？

### A

- 审查环节增加安全维度检查。
- 通过 Rules 约束安全编码规范。
- 关键安全操作人工把控。

## Agent 问题

## Q16: Agent 会乱改代码吗？

### A

存在风险。通过权限控制、小步委派、人工审查控制。让 Agent 先给方案再执行。

## Q17: Agent 任务失败怎么办？

### A

- 查看失败日志，定位卡住的环节。
- 提供更明确的指令与上下文。
- 拆分子任务，分步验证。

## Q18: 如何让 Agent 更高效？

### A

- 给 Agent 明确的目标与边界。
- 配置专用 Agent 固化能力。
- 建立验收清单，减少返工。

## Q19: 多个 Agent 如何协作？

### A

- 明确分工与交接物。
- 通过工作流编排（参考 `docs/16-case-study/`）。
- 每个 Agent 产出独立可验证。

## MCP 问题

## Q20: MCP 连接失败怎么办？

### A

- 检查配置与网络。
- 确认密钥与权限正确。
- 查看 MCP 服务端日志。

## Q21: 如何选择合适的 MCP？

### A

- 按团队工具链选择（GitHub、数据库、设计稿、文档平台）。
- 参考 `mcp/` 目录与 `docs/08-mcp/`。
- 只接入真正需要的，减少风险面。

## Q22: MCP 的写操作安全吗？

### A

- 对写操作保持谨慎，必要时人工确认。
- 控制 MCP 权限边界。
- 记录操作日志便于审计。

## 企业使用问题

## Q23: 企业如何统一配置？

### A

- Rules、Prompt、Agent 配置纳入版本库。
- 新成员按 README 一键配置。
- 凭据统一管理。

## Q24: 数据安全如何保障？

### A

- 敏感数据走本地或合规方案。
- 配置权限策略与命令白名单。
- 记录 AI 执行行为，保留审计痕迹。

## Q25: 如何保证产出风格统一？

### A

- 团队 Rules 前置到委派环节。
- 统一 Prompt 模板与 Agent 配置。
- 自动化检查 + 人工审查防线。

## 成本优化问题

## Q26: Token 消耗太快怎么办？

### A

- 简单任务用性价比模型。
- 控制上下文大小。
- 利用缓存减少重复消耗。
- 通过网关设定配额与告警。

## Q27: 如何评估模型性价比？

### A

- 建立任务完成率、返工率、成本指标。
- 定期复盘各模型表现。
- 用真实任务评测集验证切换影响。

## Q28: 批量任务如何省钱？

### A

- 简单批量任务用快速/廉价模型。
- 提前规划上下文，避免重复加载。
- 错峰执行，利用优惠时段。

## 故障排查问题

## Q29: 连接超时或请求失败怎么办？

### A

- 检查网络与代理。
- 确认服务可用状态。
- 重试并查看错误日志。

## Q30: 输出截断怎么办？

### A

- 任务过大时拆分子任务。
- 精简上下文与输出要求。
- 分步请求避免单次过长。

## Q31: 结果不符合预期怎么办？

### A

- 补充上下文与约束，重新委派。
- 提供更贴近的示例。
- 拆解任务，缩小验证范围。

## Q32: 遇到文档没有的问题在哪找帮助？

### A

- 查看官方文档与社区。
- 沉淀踩坑经验回补到本文档。

## 总结

- 安装与账号问题优先查权限、网络、凭据。
- 模型与上下文核心是"按任务路由、按需加载"。
- 代码质量靠测试、审查与 Rules 保障。
- Agent 与 MCP 强调规划先行、权限控制、人工验收。
- 企业使用统一配置、守住安全、控制成本。
- 故障排查从网络、日志、上下文三处入手。
