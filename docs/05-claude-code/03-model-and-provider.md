# Claude Code 模型与 Provider

> 站在 AI FullStack Workflow 的角度，讲解 Claude 模型体系、能力分工与多模型组合策略。不写简单模型介绍。

---

## 为什么需要了解

Claude Code 深度绑定 Claude 模型，但企业场景几乎总是多模型协作。理解 Claude 各型号的能力侧重（Coding、Reasoning、Context、Vision），并把它放进与 GPT、DeepSeek、Qwen 的组合框架里，才能做到"按任务选模型、按成本控支出"。

## 1. Claude 模型体系

Claude 模型家族围绕不同任务组织：

| 类型 | 定位 | 典型任务 |
| --- | --- | --- |
| 均衡模型 | 通用主力 | 日常对话、常规编码 |
| 代码模型 | 编码强化 | 复杂代码生成、重构 |
| 旗舰模型 | 综合最强 | 高质量产出、复杂任务 |
| 推理模型 | 深度推理 | 疑难调试、架构分析 |

Claude Code 默认基于 Claude 模型运行，其选择决定任务的质量上限。

## 2. 不同模型能力区别

### 核心差异维度

- **代码能力**：从"能用"到"高质量"，直接影响编码产出。
- **推理深度**：决定复杂问题的解决能力。
- **上下文长度**：决定能理解多少代码与文档。
- **速度与成本**：旗舰模型更强但更慢更贵。

### 选择原则

- 简单任务用均衡/快速模型，控制成本。
- 核心功能与复杂任务用旗舰模型，保证质量。
- 疑难推理用推理模型，兜底深度场景。

## 3. Coding 能力

### 优势

- 代码生成质量在业界口碑领先。
- 长上下文下的代码一致性强。
- 重构与审查建议可操作性强。

### 使用建议

- Claude Code 场景下，代码生成、重构、审查优先用 Claude。
- 通过 Rules 与上下文约束产出风格。

## 4. Reasoning 能力

### 定位

面向需要多步逻辑推导的深度任务。

### 能力要点

- 复杂问题拆解与推理链条。
- 疑难 Bug 的根因定位。
- 架构方案权衡。

### 使用建议

- 疑难问题启用推理能力，日常任务不要默认使用。
- 成本与延迟较高，按需启用。

## 5. Context 能力

### 优势

- 长上下文是 Claude 的标志性能力。
- 大型代码库与长文档场景表现稳定。

### 使用建议

- 大型项目充分利用长上下文理解整体结构。
- 超大项目仍配合检索与裁剪控制成本。

## 6. Vision 能力

### 能力要点

- 支持图像输入，可处理 UI 截图、设计稿与图表。
- 支撑"设计稿转代码"类任务。

### 使用建议

- 任务涉及图像时才启用多模态能力。
- 纯文本任务用多模态模型是成本浪费。

## 7. 多模型组合策略

结合 AI FullStack Workflow 的多模型协作框架，推荐组合：

| 任务类型 | 推荐 | 理由 |
| --- | --- | --- |
| 代码主力 | Claude | 代码质量高 |
| 通用主力 | GPT | 生态通用 |
| 成本优化 | DeepSeek | 高性价比 |
| 中文场景 | Qwen | 中文能力优秀 |
| 疑难推理 | Reasoning 模型 | 深度思考兜底 |

### 路由原则

- **按复杂度**：简单走性价比模型，复杂走旗舰。
- **按成本**：批量任务优先廉价模型。
- **按语言**：中文任务优先中文优化模型。
- **按合规**：敏感数据走本地或合规 Provider。

### 落地方式

- 通过模型网关统一管理多个 Provider。
- Claude Code 场景与 OpenCode、Codex 共享模型池。
- 路由规则对上层透明，切换无感。

## 企业如何选择

### 配置前评估

1. **盘点任务**：区分日常编码、疑难推理、中文业务。
2. **明确合规**：数据敏感度决定模型来源。
3. **设定预算**：按 Token 消耗规划组合。

### 推荐配置模板

| 角色 | 推荐 | 说明 |
| --- | --- | --- |
| 代码主力 | Claude | 质量优先 |
| 通用兜底 | GPT | 生态通用 |
| 成本优化 | DeepSeek | 性价比 |
| 中文业务 | Qwen | 中文优化 |
| 敏感数据 | 本地/合规 | 数据可控 |

### 长期维护

- 模型配置纳入版本库（不含密钥）。
- 模型更新先小范围验证，再全量切换。
- 与 `docs/02-models/10-model-selection.md` 保持联动。
- 定期复盘性价比，动态调整。

## 最佳实践

1. 按任务复杂度选择模型深度，避免一刀切。
2. Claude 做代码主力，其他模型按场景路由。
3. 用网关抽象模型池，切换对工作流透明。
4. 中文、成本、合规等场景差异化选型。

## 常见问题

**Q1：Claude Code 只能用 Claude 吗？**

Claude Code 深度绑定 Claude，但团队可通过网关将其他模型纳入统一工作流。

**Q2：什么时候用推理模型？**

疑难调试、复杂算法、架构权衡等深度思考任务。

**Q3：如何降低成本？**

简单任务用性价比模型，控制上下文，利用缓存。

## 本章总结

- Claude 模型体系围绕任务组织：均衡、代码、旗舰、推理。
- 核心优势在代码质量、长上下文与推理能力。
- 多模型组合遵循按复杂度、成本、语言、合规路由的原则。
- 企业实践用网关统一管理模型池，Claude 做代码主力。
