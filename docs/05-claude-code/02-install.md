# Claude Code 安装与环境准备

> 面向实际开发者的环境准备指南。以稳定可复现为原则，不绑定具体版本号。

---

## 为什么需要了解

Claude Code 以终端为主要形态，安装与初始配置是上手的起点。本文覆盖环境要求、安装方式、项目初始化、第一次运行、基础使用流程与常见问题。

## 1. 环境要求

### 操作系统

- 推荐：macOS、Linux。
- 支持：Windows（建议使用 WSL 获得完整终端体验）。
- Claude Code 以终端为运行环境，macOS 与 Linux 生态最为顺滑。

### 开发环境

- 需要可用的终端环境。
- 具备常见开发工具链（Node、Python、Java 等，取决于项目）。

### Git

- 需要已安装并配置好的 Git。
- 部分能力依赖 Git 工作区（提交、差异分析）。

### 账号

- 使用 Claude Code 需要 Anthropic 账号或对应订阅。
- 凭据通过登录流程或环境变量管理。

### 验证环境

```bash
git --version
```

确认 Git 可用后，即可继续。

## 2. 安装方式

### 官方安装

- 通过官方提供的安装命令安装 Claude Code CLI。
- 安装命令以官方文档为准，不同平台略有差异。

```bash
npm install -g @anthropic-ai/claude-code
```

### 验证安装

```bash
claude --version
```

出现版本号或帮助信息即安装成功。

### 登录与凭据

- 首次使用通常需要登录 Anthropic 账号。
- 凭据通过登录流程保存，或通过环境变量注入。
- 避免将密钥硬编码到仓库。

## 3. 初始化项目

### 已有项目

- 在项目根目录启动 Claude Code。
- 让它读取项目结构，理解技术栈与约定。

### 新项目

- 先初始化项目骨架（Git、目录结构、README）。
- 再使用 Claude Code 生成初始代码。

### 项目配置

- 在项目内补充规则与说明，约束产出风格。
- 将团队规范纳入版本库，保持一致性。

## 4. 第一次运行

### 启动

在项目目录启动 Claude Code，确认能读取当前项目。

### 基本交互

- 提出一个简单任务（例如"解释项目结构"），验证链路。
- 让 Claude Code 生成一个小改动，检查产出质量。
- 运行测试，确认改动不影响现有功能。

### 首次自检清单

- [ ] 版本命令正常输出
- [ ] 账号/凭据配置生效
- [ ] 能读取当前项目文件
- [ ] 能完成一次简单任务

## 5. 基础使用流程

### 委派任务

- 用自然语言描述任务：背景、目标、约束、输出。
- 让 Agent 先读代码库再动手。

### 分步确认

- 复杂任务让 Agent 先给方案，人确认后再执行。
- 每次改动聚焦一件事，便于审查回滚。

### 验证与迭代

- 让 Agent 运行测试验证改动。
- 根据反馈迭代，直到满足验收标准。

## 6. 常见问题

### 权限问题

**现象**：全局安装失败，提示无权限。

**处理**：配置 npm 全局目录为用户可写路径，避免使用 `sudo`。

### 网络问题

**现象**：安装或连接超时。

**处理**：检查网络与代理设置，必要时配置镜像源后重试。

### 凭据问题

**现象**：鉴权失败或未登录。

**处理**：重新登录，检查凭据环境变量，确认账号权限。

### 环境变量问题

**现象**：命令找不到、配置不生效。

**处理**：确认命令在 `PATH` 中，重载 shell 配置后重试。

## 最佳实践

1. 凭据走登录流程或环境变量，不写入仓库。
2. 新项目先搭骨架再让 AI 生成。
3. 团队统一安装与配置步骤，写入 README。
4. 升级前查看更新说明，评估影响。

## 常见问题

**Q1：需要 Anthropic 订阅吗？**

取决于使用方式，具体以官方说明为准。

**Q2：Windows 上能用吗？**

能用，但建议通过 WSL 获得完整终端体验。

**Q3：安装失败先查什么？**

先查网络与权限，这两类问题占大多数。

## 本章总结

- 环境要求：主流系统、Git、账号/凭据。
- 安装方式：官方 CLI 命令 + 登录配置。
- 项目初始化：已有项目直接使用，新项目先搭骨架。
- 基础使用：委派任务、分步确认、验证迭代。
- 常见问题集中在权限、网络与凭据三类。
