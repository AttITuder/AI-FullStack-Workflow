# Codex 模型与 Provider

> 站在 AI FullStack Workflow 的角度，讲解 Codex 的模型体系、能力分工与多模型组合策略。不写简单模型介绍。

---

## 为什么需要了解

Codex 的能力由模型驱动，但"模型"不是孤立的。理解 Codex 模型体系的分工（编码、推理、速度与深度的取舍），并把它放进企业多模型协作的框架里，才能避免"用一个模型包打天下"的误区。

## 1. Codex 模型体系

Codex 不绑定单一模型，而是围绕"编码任务"组织模型矩阵：

| 类型 | 定位 | 典型任务 |
| --- | --- | --- |
| Coding 模型 | 代码生成主力 | 页面、接口、模块实现 |
| Reasoning 模型 | 深度推理 | 疑难调试、架构分析 |
| 快速模型 | 轻快低成本 | 补全、简单任务、批量 |
| 深度模型 | 旗舰高质量 | 复杂任务、高质量产出 |

模型体系的逻辑：**任务复杂度决定模型深度**。简单任务用快速模型省成本，复杂任务用深度模型保质量。

## 2. Coding 模型能力

### 定位

日常编码的主力模型，覆盖代码理解、生成、修改与重构。

### 能力要点

- 理解多种语言与框架，遵循常见架构约定。
- 生成结构完整、可运行的代码。
- 支持多文件修改，保持改动一致性。
- 生成测试与审查意见。

### 使用建议

- 常规开发任务默认使用 Coding 模型。
- 通过 Rules 与上下文约束产出风格。

## 3. Reasoning 模型能力

### 定位

面向需要多步逻辑推导的深度任务。

### 能力要点

- 复杂问题拆解与推理链条。
- 疑难 Bug 的根因定位。
- 架构方案权衡与算法设计。

### 使用建议

- 只在"确实需要深度思考"时启用。
- 成本与延迟高于 Coding 模型，避免默认使用。

## 4. 快速模型与深度模型区别

| 维度 | 快速模型 | 深度模型 |
| --- | --- | --- |
| 速度 | 快 | 慢 |
| 成本 | 低 | 高 |
| 质量 | 简单任务足够 | 复杂任务更强 |
| 适用 | 批量、补全、简单 | 核心功能、疑难问题 |

### 取舍原则

- 快速模型用于"高频、简单、可批量"的任务。
- 深度模型用于"低频、复杂、一次要准"的任务。
- 组合使用而非二选一。

## 5. 多模型组合策略

结合 AI FullStack Workflow 的多模型协作框架，Codex 场景的推荐组合：

| 任务类型 | 推荐 | 理由 |
| --- | --- | --- |
| 日常编码 | GPT 系列 Coding 模型 | 通用稳定 |
| 代码高质量 | Claude | 代码质量口碑佳 |
| 成本优化 | DeepSeek | 高性价比 |
| 中文场景 | Qwen | 中文能力优秀 |
| 疑难推理 | Reasoning 模型 | 深度思考兜底 |

### 路由原则

- **按复杂度**：简单走快速/性价比模型，复杂走旗舰/推理模型。
- **按语言**：中文任务优先中文优化模型。
- **按成本**：批量任务优先廉价模型。
- **按场景**：本地/敏感任务考虑本地或合规 Provider。

### 落地方式

- 通过模型网关统一管理多个 Provider。
- Codex 场景与 OpenCode、其他工具共享同一模型池。
- 路由规则对上层工作流透明，切换无感。

## 6. 企业模型选择建议

### 配置前评估

1. **盘点任务**：区分日常编码、疑难推理、中文业务等类型。
2. **明确合规**：数据敏感度决定是否可用云端模型。
3. **设定预算**：按 Token 消耗预估成本，选择组合。

### 推荐配置模板

| 角色 | 推荐 | 说明 |
| --- | --- | --- |
| 默认编码 | GPT Coding / Claude | 质量优先 |
| 日常低成本 | DeepSeek | 性价比 |
| 中文业务 | Qwen | 中文优化 |
| 疑难推理 | Reasoning 模型 | 能力兜底 |
| 敏感数据 | 本地/合规 Provider | 数据可控 |

### 长期维护

- 模型配置纳入版本库管理（不含密钥）。
- 模型更新先小范围验证，再全量切换。
- 与 `docs/02-models/10-model-selection.md` 保持联动。
- 定期复盘各模型性价比，动态调整。

## 最佳实践

1. 按任务复杂度选择模型深度，避免"一刀切"。
2. 快速模型打底、深度模型兜底，组合使用。
3. 用网关抽象模型池，切换对工作流透明。
4. 中文、成本、合规等场景差异化选型。

## 常见问题

**Q1：Codex 只能用 GPT 系列吗？**

Codex 围绕 OpenAI 生态，但团队可通过网关将其他模型（DeepSeek、Qwen、Claude）纳入同一工作流。

**Q2：什么时候用 Reasoning 模型？**

疑难调试、复杂算法、架构权衡等深度思考任务。

**Q3：如何降低成本？**

简单任务用快速/性价比模型，控制上下文，利用缓存。

## 本章总结

- Codex 模型体系围绕编码任务组织：Coding、Reasoning、快速、深度。
- 核心取舍是"速度与深度的平衡"，按任务复杂度路由。
- 多模型组合遵循按复杂度、语言、成本、合规路由的原则。
- 企业实践用网关统一管理模型池，保持可替换性。
