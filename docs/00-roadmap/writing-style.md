# 文档写作规范

> 所有章节文档必须遵循本文档，确保知识库长期可维护、风格统一。

## 统一文档结构

每一篇章节文档按以下顺序组织：

1. **为什么要学习** — 本章解决什么问题
2. **基础概念** — 核心名词与定义
3. **工作原理** — 运行机制与设计思路
4. **实战案例** — 可复现的完整示例
5. **最佳实践** — 经验与建议
6. **常见问题** — FAQ 与踩坑记录
7. **Prompt** — 本章可直接复用的 Prompt
8. **总结** — 要点回顾
9. **参考资料** — 链接与延伸阅读

## Markdown 规范

### 标题层级

```markdown
# 一级标题（仅文档标题使用一次）

## 二级标题（章节）

### 三级标题（小节）
```

- 标题从一级开始，层级不跳跃（不出现 `#` 直接到 `###`）。
- 每级标题上下各空一行。

### 代码块

代码统一使用带语言标识的围栏代码块：

````markdown
```dart
void main() {
  print('Hello');
}
```
````

### 图片规范

- **禁止使用网络图片**（外链失效会导致文档残缺）。
- 所有图片统一存放在：

```
assets/images/
```

- 引用格式：

```markdown
![描述文字](../assets/images/example.png)
```

- 图片命名：`章节-序号-描述`，例如 `opencode-01-install.png`。

### 文本规范

- 中英文之间加一个空格（如：`使用 Git 管理`）。
- 行内代码、文件名、命令用反引号包裹。
- 重点内容用加粗或列表，避免全篇大写。
- 列表项保持句式一致，避免混用短语和句子。

## 目录规范

- 每篇文档在 `docs/<章节>/` 下，配套资源统一命名：

| 文件 | 用途 |
| --- | --- |
| `index.md` | 原理与教程 |
| `architecture.md` | 架构说明 |
| `prompts.md` | 本章 Prompt 汇总 |
| `checklist.md` | 操作检查清单 |
| `faq.md` | 常见问题 |
| `examples.md` | 案例集 |

## 写作原则

1. 先写初稿，再迭代，不追求一次完美。
2. 每个知识点配一个可运行的案例。
3. 每个文档必须能独立阅读，不依赖其他文档的隐式前提。
4. 每日增量更新（3~5 个文件），长期维护。
