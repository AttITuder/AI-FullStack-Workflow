# Project Positioning

> 本文档定义 AI FullStack Workflow 项目的定位、目标与边界，是所有内容建设的方向基准。

---

## 1. 项目背景

过去几年，AI 编程经历了飞速演进：

- **2021 年**，GitHub Copilot 把代码补全带入主流开发者的日常，人们第一次感受到"AI 替我写代码"。
- **2023 年**，ChatGPT 等大语言模型让"对话式生成代码"成为可能，自然语言与代码之间的鸿沟被大幅拉近。
- **2024 年起**，以 Agent（智能体）为代表的新一代工具出现，AI 从"回答问题"进化到"自主执行多步骤任务"，可以读取代码库、运行命令、修改文件、完成端到端的工程工作。

技术演进带来两个直接后果：

1. **个体开发者的产能差距被急剧拉大**——会用 AI 工具的开发者，与不会用 AI 工具的开发者，产出效率可能相差数倍甚至数十倍。
2. **信息碎片化严重**——AI Coding 生态每天都有新工具、新框架、新协议（OpenCode、Codex、Claude Code、MCP……），大多数人淹没在零散的教程和短视频里，难以形成体系。

市面上的内容绝大多数是"教程"，讲一个工具怎么用；却几乎没有一套"工程化的工作流"——告诉你一个项目从需求分析、架构设计、编码、测试、发布，应该如何组织 AI、如何沉淀 Prompt 与 Agent、如何让团队稳定复现最佳实践。

这就是 AI FullStack Workflow 诞生的背景：**填补"教程"与"可落地工程体系"之间的空白**。

## 2. 为什么创建 AI FullStack Workflow

### 2.1 教程会过时，工作流能长期复用

单个工具的使用方法会随版本迭代而过时，但"工作流"层面沉淀下来的原则（如何拆解需求、如何组织 Prompt、如何验收 AI 产出）具有长期价值。本项目选择沉淀工作流，而非追逐工具版本。

### 2.2 让 AI 使用从"碰运气"变成"可复制"

大多数人用 AI 是"临时起意"——遇到问题问一句，结果好坏看运气。本项目要把这些经验结构化：什么场景用什么 Prompt、什么任务配什么 Agent、什么代码遵循什么规范，全部标准化、可复制、可传承。

### 2.3 团队协作需要统一的"语言"

AI 研发不是个人行为，而是团队行为。当团队拥有统一的 Prompt 库、Rules 库、Agent 配置时，成员之间的产出风格一致、质量可预期、交接成本大幅降低。

### 2.4 长期主义的内容建设方式

本项目坚持"每天 3~5 个文件"的增量节奏，拒绝一次性堆砌大量内容。这样的内容会不断被真实使用反馈打磨，越用越准，形成正循环。

## 3. 项目目标

- 建立一套**长期维护**的 AI 全栈开发工作流知识库。
- 覆盖从**基础认知**（AI 原理、大模型、Prompt、Agent）到**工具实操**（OpenCode、Codex、Claude Code、CodeBuddy），再到**全栈实战**（Flutter、Android、Vue）与**企业研发**（工程实践、团队协作、MCP）的完整链路。
- 沉淀可复用的资产：**Prompt 库、Rules 库、Agent 库、模板库、案例库**。
- 让读者（以及未来的 AI Agent）能够按照本项目沉淀的规范，稳定地产出高质量代码与文档。

## 4. 项目使命（Mission）

> 建立一套长期维护的 AI 全栈开发工作流知识库。

使命回答"我们为谁、做什么"。本项目为自己和所有 AI 时代的开发者，持续积累一套经过实战检验、可长期维护的工作流资产，而不是一本写完就过时的书。

## 5. 项目愿景（Vision）

> 帮助开发者建立完整的 AI 软件开发工作流。

愿景回答"我们最终要成为什么"。我们希望每一位关注本项目的开发者，都能基于本项目建立起自己完整的 AI 研发体系——从工具使用、Prompt 设计，到 Agent 构建、团队协作，形成一条清晰的成长路径。

## 6. 目标用户

| 用户类型 | 特征 | 价值点 |
| --- | --- | --- |
| 独立开发者 | 全栈、Freelancer | 直接复用 Prompt 与 Agent，加速交付 |
| 移动端工程师 | Flutter / Android / Kotlin | 获取平台专属的规范、Prompt 与案例 |
| 前端工程师 | Vue / 通用 Web | 沉淀前端 AI 研发最佳实践 |
| 技术团队负责人 | 需要统一研发流程 | 引用 Rules / Agent / 工作流，统一团队标准 |
| AI 爱好者在入门者 | 刚接触 AI Coding | 通过路线图循序渐进，少走弯路 |

## 7. 项目范围（Scope）

本项目包括以下核心内容：

- **AI Workflow**：从需求到发布的完整 AI 研发流程设计。
- **Prompt 库**：按技术栈与场景分类的高质量 Prompt 模板。
- **Rules 库**：编码规范、审查规范、提交规范等约束规则。
- **Agent 库**：各技术领域 Agent 的配置、提示词与工作流。
- **MCP**：让 AI 连接外部工具与数据的标准协议与服务器配置。
- **Examples**：可运行的完整示例项目。
- **Templates**：章节、Prompt、Rule、Agent、Workflow、案例等标准模板。
- **Enterprise Best Practices**：面向企业研发的工程实践与团队协作方案。

## 8. 不包含什么（Out of Scope）

明确边界，避免内容失焦：

- **不提供付费课程或直播教学**——本项目为开源的长期维护知识库。
- **不追逐工具最新版本号**——以稳定的工作流与原则为主，工具版本仅作参考。
- **不复制官方文档**——官方文档讲"怎么做"，本项目讲"为什么这么组织、如何复用"。
- **不涉及具体公司内部项目代码**——案例均为可公开分享的示例。
- **不保证一个模板通吃所有场景**——所有资产都需要结合项目实际裁剪。

## 9. 核心原则

- **Workflow First（工作流优先）**：先有完整可复现的工作流，再谈单点技巧。
- **Best Practice First（最佳实践优先）**：沉淀经过验证的实践，而非投机取巧。
- **Engineering Thinking（工程思维）**：用版本、规范、清单、反馈闭环管理内容。
- **Long-term Maintainability（长期可维护）**：所有内容遵循统一规范，可持续迭代。

## 总结

AI FullStack Workflow 不是一个"教程仓库"，而是一套**长期维护、可复用、工程化**的 AI 全栈研发工作流知识库。本文档明确了它的背景、目标、边界与原则，所有后续内容建设都必须以此为准绳。
